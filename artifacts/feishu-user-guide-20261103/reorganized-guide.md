# DSH 飞书插件 · 用户使用指南

**飞书作为工作入口，DSH 负责执行，进展与成果回到飞书。** 从任务、会话、评论到文档和定时执行，不再反复复制需求、追问进度。

> 本指南按当前插件功能组织；保留的截图来自历史版本，仅用于界面参考。部分原图含内部任务信息，仅供内部使用，请勿直接外发。

## 1. 安装：命令行或直接对 DSH 说

需要已安装的 DSH、右侧栏插件 `dsh-better-sidebar` 和飞书 CLI `feishu-sync`。当前指南对应本地分发的 `dsh-feishu`，先获得插件目录；同名 npm 包并不等于本版插件。

### 命令行安装（DSH Web）

终端需能运行 `dsh`；将下面的插件路径替换为实际绝对路径，`web` 替换为你的目标 profile。

```bash
python3 -m pip install --extra-index-url https://artifactory.momenta.works/artifactory/api/pypi/pypi-momenta/simple feishu-sync
dsh plugin --profile web add dsh-better-sidebar "file:/绝对路径/dsh-plugins/packages/dsh-feishu"
```

安装后重载插件或重启对应 DSH，打开右侧栏「飞书」。桌面版 profile 由应用管理，优先使用下方对话安装方式。

### Prompt 安装（在 DSH 对话里发送）

将路径替换为实际插件目录，然后发送：

> 请在当前 DSH profile 安装并启用本地飞书插件：/绝对路径/dsh-plugins/packages/dsh-feishu。检查右侧栏依赖 dsh-better-sidebar 和 feishu-sync CLI，缺少时协助安装；安装后核对加载结果。先不要开启自动开工或评论协作，飞书授权由我在授权页面完成。

### 首次连接飞书

在「飞书 → 配置 → 授权」点「开始授权」，登录并确认权限。授权成功后检查受管「DSH 任务清单」，再点「立即同步」。CLI 找不到时在设置中指定 `cliPath`；不要把密码、Token 或授权码发到对话里。

## 2. 核心功能：任务与会话双向衔接

**飞书 → DSH：**自动或手动同步任务，在任务卡选择正确工作区。点击「绑定」关联当前会话但不投递工作；点击「开工」则绑定并开始处理。之后从任务卡直接进入对应会话。

**DSH → 飞书：**已有对话完成至少一轮助手回复后，点击「同步为飞书任务」，从会话最新结论生成飞书任务并绑定；让 AI「把当前进展写回飞书任务」，或开启「有实际进展才写回任务评论」，把改动、测试和结论留给同事。

> 例：把这条会话整理成一条飞书任务；之后有实际进展时写回原任务，完成前先让我确认。

一条任务对应一条会话，一条会话绑定一条任务。同步的是任务资料、关联和进展，不是把整段会话自动复制到每台设备。默认定期同步，可在「配置 → 同步规则」调整范围和间隔；面板筛选只改变显示。

**收尾操作：**「完成」写飞书完成状态并归档会话；「删除会话」不删除飞书任务；「解绑」仅断开关联。会话跑完不代表任务已经交付。

## 3. 评论协作：从手机或其他端接着推进

同事和负责人继续在飞书任务下留言，你也可以用手机补充需求；开启「配置 → 同步规则 → 评论协作」后，新评论会被识别并投递到该任务原有的 DSH 会话，处理结果再回复飞书。**飞书负责沟通入口，DSH 承接实际工作。**

负责人评论可按「处理请求」模式识别执行意图；其他协作者默认「仅回复」，不因一条普通评论就获得执行命令或改文件的权限。先在 DSH 绑定会话并启用协作，再在飞书写清请求，例如「请补充异常情况的测试，并把验证结果回复到这里」。

首次开启只建立评论历史基线，不执行旧留言；之后识别新评论并去重。常规同步只向已绑定、未完成、未挂起且可处理的会话投递，忙碌时等待，不自动新建或唤醒冷会话；任务卡评论中的「处理」可显式唤醒符合条件的原会话。

也可以从手机新建飞书任务，填写工作区并标注「触发条件：自动执行」，由已开启自动开工的 DSH 执行端在同步后接手，具体设置见第 6 节。

多人围绕共享飞书任务协作，协作者需任务访问权限；每个 DSH 执行端使用自己的个人授权，一个实例不是多个账号的授权聚合器。多端留言可以回到同一个执行端，但不是跨机器复制会话或自动分布式抢单；同一任务建议指定一个 DSH 执行实例，避免多机重复处理。

## 4. 文档生成：把工作成果留在任务上

任务卡「文档」菜单支持添加已有飞书文档，以及「AI 生成或更新」。生成时结合任务说明和绑定会话的最新结论，产出可共享的说明、设计或交付文档，并关联回任务。

> 例：根据这条任务和当前会话结论，生成一份精简的使用文档，保留必要步骤与验证结果，并关联到飞书任务。

一条任务可关联多篇文档。插件生成的文档优先原地更新，手动绑定的参考文档不会因此被替换；「配置 → 文档生成」可修改生成 Prompt，「文档监听」可定期抓取指定资料的摘要。更新会写远端正文，重要文档更新前先确认。

## 5. 洞察：早会汇报、任务诊断与履约改进

**早会汇报：**把任务与近期进展整理成「昨天做了什么、今天做什么」的口述稿；需要让同事看到时再写入任务评论。

**任务诊断：**结合优先级、工作区负载、停滞任务与延期原因，给出问题、证据和下一步建议。数字由任务快照计算，AI 负责解释，不凭空补统计。

**履约改进：**为任务设置「预期完成」，把何时交付与何时开工分开。往后改预期会保留延期／重承诺及原因，洞察据此分析准时率、偏差和反复延期，帮助调整承诺与工作量，而不是只把截止时间往后挪。

> 例：先同步飞书，再诊断最近延期的原因，结合履约记录给出改进建议和今天优先推进的任务；早会稿在面板点击「早会同步」生成。

先同步再看洞察；切换已有结果通常复用缓存，点 `↻` 才请求重新生成。齿轮中可自定义问题和 Prompt。生成洞察可能消耗模型额度；「写入评论」会真正写回飞书。

## 6. 自动化执行：按时做、自动做，不必守着页面

**新任务自动执行：**在「同步规则 → 自动开工」开启受控范围，优先选择「只开标注过的」，并限制每轮数量；在飞书清单设置工作区和「触发条件：自动执行」。同步时会检查任务条件与前置依赖，然后开工。

**每日或指定时间执行：**先绑定会话，在「同步规则 → 排期与定时 → 定时触发指令」配置到点要做什么（例如检查任务进展并回写飞书）；再在任务卡「定时」输入时间、预览并保存。也可直接对 DSH 说：

> 把这条已绑定任务设为每天上午 9 点执行，先预览，确认后保存。

触发指令是全局模板，在新建或重设定时时写入规则；修改模板后，已有规则需重设才能使用新指令。

**自动安排今天：**让 DSH 按优先级和可用时间给出时间块，先人工核对依赖，确认后落地；今日排期不等于每天自动重新规划。请区分「定时」是何时做，「预期」是何时交付，「挂起」是暂时不做；清单上的「按时执行」字段不等于已经建立每日重复规则。

定时要求已绑定会话且 DSH 自动化服务可用；保存或清除定时会影响该会话的其他自动化记录，操作前核对。定时投递不等于成功完成任务，请查看执行结果。

不需要一直打开 DSH 页面或飞书面板：由后台 Host 同步、投递和运行会话。**前提是 DSH 后台持续运行、执行机可用，且授权、网络、模型与自动化服务正常。**关闭浏览器页面与退出 DSH 后台是两回事；应用彻底退出、机器关机或休眠时，不保证执行或补跑。自动化也不能绕过需要人工批准的操作。
