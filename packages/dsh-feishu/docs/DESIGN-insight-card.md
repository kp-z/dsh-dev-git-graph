# Insight 卡片设计（早会视图）

> 对应任务：`📊 T12-Insight 卡片：早会式任务诊断与推荐`
> 目标：把「早会」要问的三件事一屏给全 —— 昨天做了什么、今天该做什么、哪里卡住了。

## 1. 位置与形态

放在任务列表**上面**、和「筛选」同一区块，默认收起成 3 行：

```
┌───────────────────────────────────────────────┐
│ 🤖 今日洞察          9 完成 · 3 在推 · 2 卡住  ⟳ │
│ 🩺 T12 三轮没提交记录；T9 卡在联调；T2 还没开工   │
│ [昨天做了什么]  [今天做哪些]  [导出早会摘要]      │
└───────────────────────────────────────────────┘
```

- 第一行：AI 小人 + 今日数字（纯本地，秒出）
- 第二行：一句话诊断（点开看 3 条，带证据）
- 第三行：三个动作
- 展开后分三块：`诊断` / `数据评估` / `回顾与推荐`

## 2. 三块内容

### 2.1 AI 诊断（按需调用模型）

输入：

| 输入 | 取多少 |
| --- | --- |
| 任务 | 编号 / 标题 / 状态 / 工作区 / 最后活动时间 / 评论数 |
| 会话 | 每条任务最近 N 轮的**助手文本首段**（各 ≤ 200 字）+ 工具调用名序列 |
| 产出 | 文档数、提交次数（从进展评论里统计） |

输出结构（固定 JSON，便于渲染）：

```json
{"headline":"今天主要在推插件，但两条任务停在验证环节",
 "issues":[{"taskNo":12,"level":"warn","text":"三轮没有提交记录","evidence":"最近 3 轮只有本地编辑"}],
 "score":{"focus":72,"throughput":60,"hygiene":80},
 "advice":"先把 T12 的跳转问题收口，再开新活"}
```

缓存键：`日期 + sha1(任务 id/title/done/最后活动)`；同一天同一状态不重复调用。

### 2.2 本地数据评估（不花 token，打开就有）

| 指标 | 口径 |
| --- | --- |
| 今日活跃 | 今天有会话轮次或进展评论的任务数 |
| 完成 / 开工 / 新增 | 按 `completedAt` / `startedAt` / `firstSeenAt` 落在今天 |
| 完成度 | 今日完成 ÷ 今日活跃 |
| 停滞 | 开工后 ≥ 2 天没有进展评论、没有文档更新 |
| 偏离度 | 任务标题关键词与「会话最近内容」的重合率 < 阈值 → 标「可能跑偏」 |
| 产出 | 今日文档数、提交次数（正则 `git commit` / `[0-9a-f]{7}`） |

偏离度是启发式的，先给粗判（高/中/低三档），不做精确打分。

### 2.3 回顾与推荐

- **昨天做了什么**：昨天完成的任务（含完成时间）+ 昨天有进展但没完成的（附最后一条进展摘要）
- **今天做哪些**：排序规则
  1. 昨天没做完的（延续性）
  2. 触发条件=自动且未开工的
  3. 停滞最久但工作区最近活跃的
  4. 编号小的（老任务优先收尾）
  每条给一句「为什么推荐你」。

## 3. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/insight?day=today` | 本地指标 + 回顾 + 推荐（纯计算，无模型） |
| POST | `/api/insight/diagnose` | AI 诊断（带缓存，可强制刷新） |
| POST | `/api/insight/export` | 把上面的内容写成一条飞书评论 / 一篇文档 |

## 4. 成本与隐私

- 一次诊断控制在 **4k token / 15 条任务**以内，摘要各截 200 字。
- 只发任务标题、状态、摘要首段；**不发代码、不发完整对话、不发文件路径细节**。
- 默认**不自动调用**：打开面板只算本地指标，点 🤖 才诊断。

## 5. 降级

| 情况 | 表现 |
| --- | --- |
| 没有模型 / 超时 | 显示本地规则诊断（停滞项、无产出项），并标注「AI 不可用」 |
| 任务为空 | 空态：「今天还没有可评估的任务」 |
| 会话读不到 | 只用任务自身状态算指标 |

## 6. 分期

| 期 | 内容 | 预估 |
| --- | --- | --- |
| P1 | 本地指标 + 昨日回顾 + 今日推荐（纯计算，无模型） | 1 天 |
| P2 | AI 诊断（缓存 + 降级 + 展开看 3 条） | 1 天 |
| P3 | 导出为飞书评论/文档，接进「早会」流程 | 半天 |

## 7. 待定

1. 完成度/偏离度口径是否按上表写死？
2. AI 诊断默认关闭（手动点）还是每天首次打开自动跑一次？
3. 卡片默认收起还是展开？

# v2：早会同步 + 趋势看板 + 数据落盘

## 1. 三个入口合并成一个

之前是「今天做了什么 / 昨天做了什么 / 今天做哪些」三个按钮，各开一块。
现在统一成 **早会同步**，一次展开按顺序给完：

```
① 今天做了什么   （AI 一句话 + 完成清单 + 推进清单）
② 昨天做了什么   （完成清单 + 推进清单）
③ 今天先做这些   （推荐 + 每条理由）
④ 趋势           （柱状图 / 折线图 / 旭日图）
```

## 2. 三张图各自回答什么

| 图 | 数据 | 回答的问题 |
| --- | --- | --- |
| 柱状图 | 近 7 天「完成数 / 新开工数」 | 这几天产出节奏是涨还是掉 |
| 折线图 | 近 14 天 WIP（在跑任务数） | 我是不是在同时堆活（WIP 越高，单件越慢） |
| 旭日图 | 内环＝状态占比，外环＝该状态下按工作区拆分 | 我的注意力压在哪些项目上、哪里在堆积 |

实现上不引第三方库：柱状图用 div 高度，折线图和旭日图用 SVG path。
旭日图是一个真正的两层结构（外环按内环的扇区再细分），不是两个饼图叠在一起。

## 3. 数据落盘（可跟踪、可校准）

- `state.metricsByDay`：每天一条快照（完成/开工/新增/活跃/WIP/文档/完成度/偏离度/周期中位数与 85 分位）。
- `<DSH_HOME>/dsh-feishu/metrics.jsonl`：同一份数据按天一行写出，方便外部脚本/报表消费。
- 历史天数没有快照也能算：完成/开工/新增都落在任务时间戳上，WIP 用「当天结束时还没完成」还原——
  装上插件当天就能看到过去两周的形状，不用等两周攒数据。

## 4. 评估口径（来自 docs/KNOWLEDGE-task-completion.md）

| 指标 | 口径 | 依据 |
| --- | --- | --- |
| WIP | `started && !done` | Little's Law：`周期 ≈ WIP / 吞吐`，WIP 高则单件慢 |
| 周期时间 | `completedAt - startedAt` 的中位数与 85 分位 | 给区间不给单点预测（计划误区） |
| 切换税代理 | 当日活跃任务数 | 切换成本研究：切换后平均 ~9.5 分钟回到状态 |
| 完成偏好 | 开工早但长期未完成的任务 | 短任务偏好导致长任务被推迟 |
| 里程碑 | 累计完成 vs WIP 两条线的斜率 | 反向收敛、同向发散 |

## 5. 明确不做

- 不做心理/情绪推断。
- 不做「预计完成时间」这种单点预测，只给历史周期分布。
- 不做实时刷新（图表在打开早会同步时拉一次，数据本身按 5 分钟节流记录）。


## v3：紧凑布局（左文右图，收起也看图）

```
┌──────────────────────────────────┬──────────────┐
│ 🤖 今日洞察  共9·在跑7·完成0      │ 完成·7天 ▁▃▅ │
│ 一句话结论（AI 或本地兜底）        │ 在跑 7  ╱╲   │
│ [早会同步][诊断][写入评论][展开]   │ 环·状态      │
├──────────────────────────────────┴──────────────┤
│ （展开）今天做了什么 / 昨天 / 今天先做            │
└─────────────────────────────────────────────────┘
```

- 两栏 `grid: minmax(0,1fr) 128px`：左边文字，右边 128px 固定宽的迷你图表。
- 迷你图表**不展开也画**：柱（近 7 天完成）、折线（近 14 天 WIP）、环（状态分布）。
- 展开后的清单横跨整宽，不挤在左栏里。
- 趋势数据在面板打开时就拉一次（本地计算，很轻），不再等点「早会同步」。


## v4：AI 选图（数据仍然本地算）

### 布局

```
┌───────────────────────────────────────────────┐
│ 🤖 今日洞察  共9 · 在跑7 · 未开始2        ⚙   │  ← 顶栏整行
├─────────────────────────────┬─────────────────┤
│ 结论（AI 或本地兜底）         │ 图 1  AI 选的    │  ← 中间块左右分
│ AI 补一句判断（commentary）   │ 图 2            │
│                              │ 图 3            │
├─────────────────────────────┴─────────────────┤
│ [早会同步][诊断][写入评论][展开]                │
└───────────────────────────────────────────────┘
```

### AI 与数据的分工

| 谁 | 决定什么 | 为什么这样分 |
| --- | --- | --- |
| AI | 用哪种图（bar/line/pie/sunburst）、展示哪个数据集、标题与理由、以及一句自己的判断 | 图的「观点」需要理解上下文 |
| 本地 | 数据集里的每个数字 | 模型编数字是最容易出错的环节 |

### 数据集白名单

`done_by_day_7` · `started_by_day_7` · `wip_by_day_14` · `state_distribution` · `workspace_distribution`

模型返回的 `type` / `dataset` 不在白名单里会被直接丢弃（不报错、不渲染错图）。

### 缓存与触发

- `state.insight` 按「日期 + 任务签名」缓存；打开面板或点「早会同步」时，当天没有结论就自动生成一次。
- 点「诊断」强制重生成（会花 token）。
- 旧版提示词（没有 charts/commentary 字段）在升级时自动替换为新默认，否则模型不会吐图表。


## v5：一张饼图占一半宽，文字收进 hover

- 中间块 `grid-template-columns: minmax(0,1fr) minmax(50%,1fr)`：饼图至少半宽（实测 349/698）。
- 只画**一张**饼图：AI 仍然选数据集（状态分布 / 工作区分布优先），形状统一为环形饼。
- 文字只留两行结论；完整结论、AI 的判断、三个粗分放 `title`，悬浮即见。
- 饼图 96px + 最多 4 条图例，视觉重心落在图上而不是文字上。
