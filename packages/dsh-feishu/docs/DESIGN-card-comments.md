# 任务卡评论区

## 本轮计划

先核对T45实际状态与评论同步记录；复用原任务卡结构，增加按需展开线程及同步诊断；最后隔离Host/UI回归并检查当前GUI，不拿真人评论触发执行。

## 界面

底部操作栏新增线框对话图标「评论」，无已加载数据不编造数量。展开是卡片内细分隔线程，不套新卡片。作者/角色/时间/状态弱化，正文最多四行，实际溢出才显示「展开」。原生回复贴近父评论并缩进。按钮仅「刷新」「处理」「对话」「展开/收起」，细节在title里。

评论历史与处理账本合并显示，历史可看，自己回复明确仅查看；unknown为「待核对」，reply_pending为「待回复」，不伪装正在处理。同步诊断可看最近读取、数量、新增和首次基线/失败/状态核验/等待原因。

## 数据与行为

GET tasks/comments?taskId&refresh 仅拉详情和账本，不建baseline、不入执行队列；完整性失败仍展示部分历史和错误。独立缓存与展开映射，动态区域更新不参与整卡signature，复用公共轮询，不每卡新建timer。

POST comments/action submit必须用户明确点击。复核现有绑定、状态、作者和配置；历史评论可人工提交，AI自身出站ID拒绝，已投递/已回复/已dispatch后忽略都不重复。busy等待，manual允许唤醒原绑定冷会话但不创建或换绑。默认自动同步仍不唤醒冷会话。

新增tasks.comment-history能力探针，旧Host禁处理并显示重载提示。查看/刷新绝不执行。

## 验证

commentHistory.mjs覆盖历史首次基线、诊断、手动提交、忙等待和重复防护；cardCommentsBridge.mjs真实apply+fakeCLI/API十组验证GET不执行与POST模式/绑定/回执去重；cardCommentsPanel.mjs覆盖独立缓存、重绘保留、单飞、弱状态标签和UI安全禁用。相关旧回归通过。

当前GUI已看到评论按钮和展开框，旧Host未加载新GET接口时正确显示重载提示。未伪造UI数据作视觉成功，不擅自重启正在运行的DSH。新历史接口需正常重载Host后使用。

T45只读核对当时开关enabled=true，已绑定/未完成/未暂停，6个seen ID、inbox为空，远端读取也为6条。不能断言用户最新留言已被处理，本轮通过诊断让后续可区分未拉取、基线和待处理。
