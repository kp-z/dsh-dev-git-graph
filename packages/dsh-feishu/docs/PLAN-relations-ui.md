### P0-2 一键整理的「落库后可见」（结论条已上线，临时展开未做）
- 现状：接受完成的任务关系后，因为已完成默认隐藏，画布上仍然空。
- 方案：接受后若命中隐藏节点，结论条上给一个「显示已完成」按钮（已实现）；再加一条**接受即临时展开**的开关（默认开），3 秒后自动收起回原状态。
- 验收：`overviewPanel` 断言「接受 → 隐藏节点临时可见 → 超时后恢复隐藏」。

### P0-3 画布空态与多图布局
- 现状：多个目录时每张图 `min-height: 220px` 平铺，5 个目录就要滚很久；空目录卡片仍占位。
- 方案：>2 张图时改成**折叠式堆叠**（默认只展开第一张，其余显示一行摘要「QVIZ · 3 项目 · 5 任务」），点标题展开。
- 验收：`overviewLayout` 断言 `graphs[i].collapsed`；`overviewPanel` 断言只渲染第一张画布。

## 每轮的工作方法（定时任务照这个跑）

1. `git status` 看有没有别人正在改的文件，**不碰并发修改的文件**。
2. 从 P0 往下取 1–2 项，先写「验收口径」，再改代码。
3. 改完必须：`node test/overviewLayout.mjs`、`node test/taskNodeCard.mjs`、`node test/overviewPanel.mjs`、`node test/graphViewport.mjs` 全过；
   动到宿主逻辑时再加 `pnpm test` 全量。
4. 视觉相关的改动，用真实组件生成一张离线预览（`/tmp/gen-ui-preview.mjs` 的写法）确认尺寸/不溢出。
5. 每轮结束：勾掉计划里的项、在 commit message 里写清「改了什么 + 怎么验证的」。
