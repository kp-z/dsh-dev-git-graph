# dsh-feishu

把飞书接进 DeepSeek Harness：**配好授权，定时把任务和文档同步到本地；任务可以一键开成 DSH 会话直接开工。**

## 评论协作

右上角「配置」→「同步规则」→「评论协作」，默认关闭。开启后，常规同步完整读取已绑定、未完成、未挂起任务的评论；第一次建立历史基线，不执行旧评论。负责人模式可设为「在绑定会话内处理」，其他人模式可设为「只回答问题」。不创建新的问答会话；忙碌或未激活的会话等待下一轮同步，不因评论恢复冷会话。

新增评论按任务 ID + 远端评论 ID 持久化去重。编辑已有评论不自动重做。角色、绑定和任务状态在投递及处理前重核；非负责人轮次的 Host guard 只允许当前任务详情与 `feishu_comment_reply`，不得运行命令、改文件、读其他会话或修改任务。模型判断负责人评论意图，普通讨论不应当作修改指令。

处理后显式调用 `feishu_comment_reply`，传投递的 `taskId/commentId/text`。它只能回复当前正在处理的评论。所有 AI 写回统一显示 `🤖:`；**防循环只认出站账本记录的远端评论 ID，不依赖正文前缀或发言账号**。正常进度回评不会与评论处理结果重复发送。

回复默认使用 Task v2 原生 `reply_to_comment_id` 关联。配置「回复提及作者」可显式选择「任务富文本 @ 作者」（`mentionMode=task-v1`）：仅带作者提及的回复走官方 Task v1 `rich_content`，需要旧版评论权限；普通评论仍走v2。已在隔离真实任务验证服务器解析为实际用户名，且v1/v2评论ID及回复关联互通。**不保证通知实际送达，不拼接假的 @姓名**；权限失败不换接口重发，重试保留原通道。创建评论无远端 uid 幂等参数；成功回执缺失或超时时置为未知，冻结该任务自动评论处理，不能盲目重发。收件箱提供忽略输入和确定失败回复重试；未知出站需管理员依据远端评论 ID 核对，不能仅忽略输入解除账本锁。

状态独立保存在 DSH_HOME/dsh-feishu/comments.json，原子替换并同步临时文件；锁阻止多个进程同时处理，死进程锁可回收，异常锁需人工检查。进程崩溃恢复对已投递但未确认项目保守停止，不保证断电或远端 exactly-once。

验证：`npm run test:offline` 不调用真实 CLI/API；包含 Python fake API、持久状态机与真实 Host apply/路由/工具的 fake 端到端。`npm test` 仍包含需要个人授权且可能读取同步真实任务的旧 smoke。Host 更新需重载插件或重启 DSH；仅刷新面板不代表新 Host 能力已加载。

## 任务卡操作与关联展示

任务标题与工作信息为主，次要操作集中到底部。已绑定文档 Tag 常驻任务卡，点击直接打开；底栏「文档」菜单仅收纳添加文档和 AI 生成/更新操作；「挂起 / 恢复」为低权重文字按钮，原因输入仅点击后弹出。删除、解绑及关联编辑收进「···」，不在卡片正文常驻表单。

没有关联不显示关联区；已有依赖用细箭头表达「前置 → 本任务 → 后置」，来源/派生用虚线箭头区分。多条默认显示一个短任务名与 +N，点击查看局部关联；仅在用户打开管理入口后渲染编辑控件，避免为每张卡构建完整候选列表。

任务区「筛选 / 立即同步」靠标题行右侧排列。卡片关联节点与 +N 使用浅底细边框 Tag，字号字重与其它工作信息一致，不突出本任务。关联编辑用一行「左侧任务 Tag 下拉 → 右侧任务 Tag 下拉」表达关系，当前任务默认放在对应一侧，点击另一侧展开搜索与可滚动候选列表，选中后才允许添加；已有关系按类型列出，可独立移除。添加成功留在面板便于继续配置，失败保留搜索与选择并显示具体原因；不再使用长原生任务下拉框。

## 性能与响应

面板加载先取本地状态，再分批加载洞察/图表/履约，隐藏时不轮询；state读取采用singleflight，同一时刻多个刷新共享一次请求。轮询按任务ID复用卡片，仅内容或必要上下文变化才重建，过滤隐藏后恢复仍可复用；相同图表数据不重新初始化。签名比较完整展示数据，避免同长度文本变更、挂起/关系/会话阶段变化漏刷新。工作区写操作期间旧state响应丢弃并重取，避免旧快照覆盖新选择。

Host `/api/state` 立即返回本地快照，自动化目录后台singleflight缓存刷新；刷新慢时先使用缓存，稍后轮询更新。快照一次构建关系图索引和工作区列表，避免每卡重复全量扫描。

工作区换绑本地落盘成功即返回 `{writeBack:{pending:true}}`，飞书写回后台按task串行，`state.workspaceWrites` 持久保存最新值/版本/pending/error；旧版本完成不覆盖最新绑定，失败下轮有界重试。卡片用轻量提示表示待同步或写回失败，不阻塞选择。同步任务的远端旧字段不能盖掉本地待写值。

性能回归：`test/performancePanel.mjs` 验证无变化零卡片重建、单任务变更只重建一张、closure新鲜、图表复用、请求去重与竞态；`test/performanceBridge.mjs` 用慢mock目录/补充通道验证状态读取不阻塞、后台写回与失败重试。均纳入 `npm test`。本地采样不是跨设备性能保证；Host源码更新仍需重启当前DSH。

## 任务筛选面板

筛选采用条件组，不再叠加「显示某状态」开关。完成状态、处理状态、推进阶段、依赖状态、优先级与工作区使用同一语义：**不限 / 只看所选 / 排除所选**，每组可多选；同组任一匹配，跨组全部满足，再与关键词组合。

- 内置视图为「日常」（排除已完成、排除挂起）、「全部」（清空条件）和「项目」（只看当前会话所属工作区，完成/挂起不限）。项目视图跟随会话上下文，按工作区ID或路径精确匹配；旧任务仅有名称时仅在登记表精确唯一命中后归一化，重名不猜；创建新任务时立即保存项目ID，无需等待飞书字段同步；没有上下文明确提示且不退回全部。用户命名保存的筛选方案与它们同排显示，切换替换整套规则并收起详情；不内置「仅挂起」，需要时可自行配置保存。
- 每个条件组可以独立只看或排除，例如「只看 P0/P1」＋「排除挂起」＋「只看已绑定」＋指定工作区。不提供依赖数据的任务标为「未知」，不冒充就绪。
- 具体条件与摘要默认隐藏，点击「筛选」才展开编辑；重开面板也默认收起，但保留生效规则。摘要支持逐组移除；移除组设为不限，不偷偷回到默认。结果计数基于本地快照，空结果提示检查条件，不代表飞书没有任务。
- 模板行提供「＋ 新模板」，展开配置后命名保存；可更新已有自定义模板，也可覆盖日常/全部/项目三个内置模板，并单独还原为原始配置。删除只针对自定义模板，不修改当前规则。模板配置只保存在当前浏览器，不同步飞书；存储失败明确提示。
- 「清空全部条件」始终解除所有限制，不受「全部」模板覆盖影响；还原内置模板只恢复该模板原始规则，不删除其它模板。「项目」覆盖后仍跟随当前项目，额外条件可保存。只看模式未选值时匹配零任务；排除模式未选值时不排除任何任务，界面明确提示。
- 条件保存到浏览器本地，旧版完成/挂起开关和工作区选择自动迁移。已选工作区暂时不在快照中仍保留条件，不静默清除。将来扩展状态，只需扩展对应条件组选项，不添加新开关。

## 挂起 / 恢复

任务暂时不做时，卡片点「挂起」，可填写原因；之后点「恢复」。挂起不是完成，不修改预期完成时间，也不删除会话、文档或前后任务关系。

- 挂起会归档**这条任务绑定的会话**（`stopActivity:true`，停止正在运行的工作），不级联归档前置/后置任务的会话。挂起状态独立持久化，自动开工、人工开工、今日排期和工作区自动补挂都会跳过挂起任务；挂起期间不可换绑或解绑，先恢复再操作。
- DSH 没有直接 pause 接口。归档的宿主停止服务会将该会话活动自动化设为 inactive，保留旧记录和投递历史。插件捕获本次挂起前 active 的规则；恢复解归档后，按原规则创建新的活动自动化（新 ID），不删除旧历史。旧 inactive、原先已归档、后来被删除的规则不恢复；过期一次性提醒不补发。
- 恢复不自动开工、不创建新会话。原会话重新出现在项目列表后可继续；失败时保留恢复凭据，返回 warnings，可以再次恢复。会话或定时恢复发生异常时，任务继续保持挂起，避免提前自动推进。字段写回失败则不回滚已完成的本地操作。
- 筛选的「处理状态」默认排除挂起，可切换不限、只看挂起或组合其它条件；需要「仅挂起」时在筛选里配置并保存为自己的方案。隐藏仅影响列表，未完成统计与履约不把挂起视为完成。
- 工具 `feishu_task_suspend`：`action=suspend|resume|status`（默认 suspend），可传 `taskId/reason`；默认创建/写入飞书清单「处理状态」单选（正常/挂起），`writeBack=false` 仅本地。没有清单或权限不足时明确提示并保留待写状态。飞书列目前是单向展示投影，不支持在飞书改列自动触发归档。

测试：`node test/suspensionBridge.mjs`（离线 mock Host）和 `node test/suspensionPanel.mjs`（真实面板函数的 DOM/语法回归），已纳入 `npm test`。已有链接安装的 Host 仍需重启 DSH 加载新接口；不自动重启用户正在运行的会话。

## 任务关系（前置 / 后置 / 来源）

任务卡新增可展开的「任务关系」，可选任务添加前置、后置或来源。前置与后置是同一条有向依赖的两端；来源独立记录，不会因为同主题就阻塞执行。

- `feishu_task_relations`：`get` 查看；`suggest` 返回 AI 建议但不保存；`set` 保存。`mode=merge` 默认追加，`replace` 仅替换显式传入类别，空数组清空该类。依赖与来源均拒绝自环、环路和不存在的任务 GUID。
- 默认同步飞书 **Task v2 原生依赖**（`prev`/`next`），同清单可在飞书甘特图展示；`writeBack=false` 只保存本地。写回失败返回 `remote.ok=false`，本地关系保留为待同步并在下一轮重试。
- `fields=true` 才另外创建/写入清单文本列「前置任务」「后置任务」「来源任务」（一行一个 GUID）。这是展示投影，**不是多维表格的关联记录字段**；不自动读取文本列反向改依赖，也不覆盖已有同名非文本字段。
- `feishu_task_create` 支持 `predecessorIds`、`successorIds`、`sourceTaskIds`、`reason`。已绑定会话用 `followUp=true` 创建后续任务：原绑定不变，新任务自动追溯来源任务与创建会话；需要等待来源完成时再显式传 `predecessorIds`。
- `autoRelate=true` 是明确启用的创建增强：只在同工作区/清单候选中由 AI 推断并保存，经 GUID 范围与环检测；默认不猜关系。`suggest` 则适合先检查建议。AI 不可用/输出非法时不撤销已创建任务，失败情况随创建结果返回。
- 关系边持久保存 `source/reason/sessionId/createdAt`；快照增加依赖/来源边数、被阻塞/就绪任务数。自动开工前刷新原生依赖并检查前置完成；未知前置保守阻塞。**已有 DSH 定时任务由宿主直接投递，不受此自动开工门控；人工开工也不强制阻止，只在档案提示依赖。**

飞书官方依据：[添加依赖](https://open.feishu.cn/document/task-v2/task/add_dependencies)、[移除依赖](https://open.feishu.cn/document/task-v2/task/remove_dependencies)、[获取任务](https://open.feishu.cn/document/task-v2/task/get)。已用官方 SDK 类型核对添加的 `type: prev|next + task_guid` 和移除的仅 `task_guid`；添加需要当前与关联任务的编辑权限。任务清单自定义字段支持文本/数字/日期/成员/单选/多选，没有记录关联类型。多维表格另有单向/双向记录关联，但当前插件同步的是任务清单，未接入 Bitable 存储。

验证：关系纯函数、Host 接线和 Python mock 通道已覆盖；`npm test` 运行全部回归（关系子进程测试需要 `cc`，Python mock 需要 `python3`）；没有对用户真实任务执行测试关联。链接安装的宿主更新需重启 DSH，面板文件刷新可先出现新控件，不代表旧宿主已经支持新接口。

## 它做什么

| 能力 | 说明 |
| --- | --- |
| 授权 | 面板里点「开始授权」，走 `feishu-sync-cli` 的个人 OAuth；令牌由 CLI 自己保管和刷新，插件不碰密钥 |
| 任务同步 | 按间隔（默认 30 分钟）拉 `task list`，落到本地快照；支持只拉未完成、关键词过滤、截止日窗口 |
| 文档同步 | 监听若干 wiki / 文档链接，抓标题、最后修改时间和正文摘要 |
| 手动开工 | 在侧边栏点「开工」= **在当前对话里开工**：任务绑到这条会话并把描述投递进来；不在会话里（独立窗口）时才新建 |
| 自动开工 | 三档：关 / 只开标注过的 / 所有新任务（默认关，每轮最多 N 条）。标注方式见下 |
| 任务 ↔ 会话绑定 | 开工时自动绑定；面板可「打开会话 / 复制 ID / 解绑」，也能把当前会话认领给某条任务（`feishu_task_session`） |
| 飞书式卡片 | 任务卡显示负责人/关注人头像与姓名、清单名、清单自定义字段（状态/优先级…）以及工作区解析结果 |
| 任务详情 | `feishu_task_detail` 一次拿全：状态/负责人/关注人/创建人/时间/清单字段/文档/**评论/子任务/附件**（后三样走补充通道，120s 缓存，缺 scope 时降级显示原因） |
| 进展回写 | 每个 turn 结束，把这一轮结论写进绑定任务的飞书评论（去代码块、≤600 字、同会话最小间隔可调、失败下次补发一次） |
| 会话感知 | 开工时投「任务档案」（全字段）；可选「绑定即注入」与「变化推送」两个开关，默认都关 |
| 任务文档 | 卡片里直接「＋ 文档」贴链接绑定（绑过就不再显示）、`✎` 改链接、`✕` 解绑；绑定/解绑/改链接都**立刻**同步飞书「文档」字段，任务改名时它生成的 docx 标题也跟着改 |
| 截图 | `docs/shots/` 下有整窗与面板截图，见下方「截图」一节 |
| 模型工具 | `feishu_tasks`（读任务）、`feishu_sync`（立即同步）、`feishu_doc_read`（读文档）、`feishu_task_session`（任务↔会话）、`feishu_task_report`（把会话结论回写到绑定任务）、`feishu_task_comment`（写评论） |
| 面板 | 右侧栏「飞书」页签：授权状态、同步设置、任务列表（开工 / 略过）、文档监听 |

## 优先级

清单上有一个单选字段「优先级」，选项 `P0` / `P1` / `P2` / `P3`（字段不存在时，第一次设置会自动建出来）。

- **卡片上很显眼**：左边一条色条 + 标题前的实心徽标，红 / 橙 / 蓝 / 灰 = P0 / P1 / P2 / P3
- **点徽标就改**：弹出 P0~P3 + 「清除优先级」，改完立刻写回飞书
- **没设过的卡片**显示虚线 `--` 小块，点击即可补
- **列表排序**：当前对话绑定的那条永远置顶；其余按 P0 → P3 → 未设置
- 洞察的上下文里会带上「优先级=P0」，两个 tab 的默认提示词都把它写进判断框架：P0 先进今天的排期，P1 优先于没排过的，P2/P3 只在接近收口或卡住别人时才提

字段名可以在 `settings.taskFields.priority` 改（默认 `优先级`）。

## 依赖

- 本机装好并已授权 `feishu-sync-cli`（`python3 -m pip install feishu-sync`，或 uv tool）。
  插件会在 `~/.local/bin`、`/opt/homebrew/bin`、`/usr/local/bin` 里找；找不到就在面板里提示，
  也可以在设置里把 `cliPath` 写死成可执行文件的绝对路径。
- 未授权时插件照常加载，只是面板显示「需要授权」——不会拖垮 profile 启动。

## 在飞书任务里配置「工作区 + 自动开工」

**首选：清单自定义字段。** 在任务所在清单上加两个字段：

| 字段 | 类型 | 值 |
| --- | --- | --- |
| 工作区 | 文本 | DSH 里已登记的工作区标题，或绝对路径 |
| 触发条件 | 单选 | 人工触发 / 自动执行 / 按时执行 |
| 开始时间 | 任务原生「开始时间」 | 按时执行的触发时刻 |
| 结束时间 | 任务原生「截止时间」 | 过点不再自动开工 |

字段名可以在面板设置之外通过 `settings.taskFields` 改（默认就是「工作区」「自动开工」）。
读/建这些字段需要 `task:custom_field:read` / `task:custom_field:write` 两个 scope；
插件用 `feishu_api.py` 复用 feishu-sync-cli 的 token 调对应接口，不另存一份凭据。

旧任务仍可在描述里写（字段不存在时才生效）：

```
工作区: dsh-plugins
自动开工: 是
```

- 工作区名匹配的是 DSH 里**已登记**的工作区标题（也接受绝对路径）。拼错不会乱开工，而是把错误显示在任务上。
- 三档开关：`关闭` / `只开标注过的` / `所有新任务`。`自动开工: 否` 在「所有新任务」下也会被跳过。
- 也可以只在标题里写 `[ws:dsh-plugins]`；什么都不写时用默认工作目录。
  （原设计里「任务清单名当工作区名」的兜底保留了代码，但 `task list --json` 只回清单 guid 不回名字，
  实际不会生效——等 CLI 带回名字再启用。）
- 每轮最多开 `maxAutoStartPerRun` 条（默认 1），避免一次同步把 token 全烧掉。
- 自动开工始终**新建**会话（没有「当前会话」这个概念）；手动开工才复用当前对话。
- 「按时执行」现在是**精确 arm**：插件算出最近的触发时刻、只定时到那一点，到点立刻跑一轮同步——
  不需要给未来任务预建空会话，也不依赖 cron（旧版的 30 秒盲轮询已经换掉）。
- 飞书里填的开始时间只是**输入之一**：同步时会合成一条本地排期兜底，真正权威的是下面的
  「一句话排期」层。

### 工作区字段会自动补写

任务卡上算出来的工作区，不只是给你看——同步时还会**写回任务的「工作区」自定义字段**：

- 只填空值（你自己填过的不会被覆盖），一轮最多补 5 条，避免拖慢同步；
- 来源优先级：任务自己声明的 → 绑定会话所属的工作区（查登记表的 `sessionIds`，宿主重启过也能查；查不到再退回
  `inspect` 拿 cwd 反查）；
- 开工 / 绑定之后立刻补一次，不用等下一轮同步。
- **选项自动补齐**：同步时把「登记表里的工作区 ∪ 任务上出现过的名字」和字段现有选项比一次，
  缺的补上（只在缺的时候发请求，稳态下就是一次内存比较）。所以你在 DSH 里新建一个工作区、
  把会话绑给任务，飞书那边的下拉里就会自动出现这个选项，不用先手工加。
- **字段类型支持文本 / 单选 / 多选**：单选写的是选项 guid（不是文本）；选项里没这个名字时，
  桥接会**带着现有选项的 guid** 追加一个——不传 guid 的整表重写会重建所有选项，
  所有任务上的旧值就全失效了（踩过）。

所以默认清单里那些「跑了半天但工作区空着」的任务，会慢慢补齐；本来就没有会话、也没声明工作区的任务保持空。

**绑定按 id，不按名字**（v0.15）：工作区名字在 DSH 里可以改、也允许不同目录同名，所以本地记的是
`state.workspaceLinks[taskId] = {id, path, title}`。飞书上的「工作区」字段仍然是人话名字，
但它只负责显示和**第一次**绑定；之后再认工作区一律走 id（改名不断链），改完名还会把新名字写回飞书。
匹配不再猜：去掉了「包含匹配 / 路径后缀 / 绝对路径兜底」，认不出来就显式标失效，
未登记的绝对路径给一个「登记为工作区」按钮；卡片上的工作区标签可以直接点开下拉换绑
（按 id 绑，换完把新名字写回飞书字段）。

### 早会同步：直接念的口述稿

「早会同步」这张卡是按**口述**写的，不是周报：新增 `standup` 字段，给两段可以直接照念的稿子
（昨天做了什么 / 今天做什么），每件事都要说清「所以什么变了」，项目代号第一次出现要解释，
并禁用「顺利 / 高效 / 大幅提升 / 闭环」这类自嗨词。展开卡片能看到「口述稿（可直接念）」，
「写入评论」导出的文本也会把口述稿放在最前面。

### 逾期自动归因

预期过了还没完成的任务，插件会用默认模型结合「最近对话 + 改期记录 + 最后活动」给一个归因
（估时不准 / 等依赖 / …），落在 `state.delayAttributions` 里，卡片上显示 `🤖 估时不准`。
一轮最多 3 条、失败 6 小时退避；改期后旧归因自动失效并重算；人工写的改期原因优先。

## 时间自动化：一句话排期（AI 排期层）

> 卡片上这枚叫 **`⏰ 定时`**（旧的「排期」），和 **`📅 预期`** 是两件事：
> **定时 = 什么时候做**（到点往会话里推一条指令）；**预期 = 什么时候交**（承诺，用于算履约）。

以前「什么时候开工」只能去飞书任务上手工填开始时间；现在多了一层**话 → 规则 → 准点开工**。
卡片上的 `⏰` 只显示两段（规则 + 下次）：`⏰ 每天 09:00 · 明天`、`⏰ 每 1 小时 · 今天`、
一次性 `⏰ 明天 15:00`；暂停收个 `⏸️`，其余细节进悬停。

**真相源是 DSH 的自动化任务**（`@deepseek-ai/dsh-schedule`）：有绑定会话的任务，
「定时」显示的就是那条自动化；在面板上改时间等于 create/update 它，清除等于 delete 它。
两个硬约束：**没绑定会话不能排期**（⏰ 变禁用态）；**一个会话只允许一条自动化**
（保存时多余的会被收敛掉）。本地 `state.schedules` 已停用，老数据不再显示也不再触发。
到点发什么指令由 `settings.schedule.automationPrompt` 决定，默认
「继续这条任务：先制定计划，然后按计划开始执行。」。

```
你/模型说一句「下周一早上九点半」  →  schedule.js 编译成 spec
                                   →  调度器 arm 到那一刻
                                   →  到点自动开工（可写回飞书开始时间）
```

完整设计见 [docs/DESIGN-ai-scheduling.md](docs/DESIGN-ai-scheduling.md)。

### 三种排期入口

| 入口 | 用法 | 适合 |
| --- | --- | --- |
| 面板任务卡 | 点 `⏰ 定时`，输入「明天下午三点」「每隔一小时」→ 预览 → 保存 | 临时改时间 |
| 模型工具 `feishu_task_schedule` | 「把这条任务排到每周一早上 9:30」「先把截止前两小时设上」 | 对话里顺手排 |
| 模型工具 `feishu_plan_today` | 「今天怎么安排」→ 给顺序和时长 → 预览 → 落地 | 一天的整体安排 |

三者落的是同一份规则（`state.schedules[taskId]`），面板、工具、飞书字段看到的「下次」永远同一个。

### 能表达什么

| 说法 | 规则 |
| --- | --- |
| 明天下午三点 / 今晚八点 / 30 分钟后 | 一次性 |
| 每天 9:00 / 工作日 9:00 | 每天 / 只在周一~周五 |
| 每周一早上 9:30 / 每周一、三 10:00 | 每周 |
| 每月 1 号 10:00 | 每月 |
| 截止前 2 小时 / 提前一天 / 开工后 1 小时 | 相对锚点（落地时算成绝对时刻） |
| 再加一句「午休别打扰」「只在 9:00-19:00」 | 免打扰 / 触发窗口 |
| 「到 12 月底」 | until |

跨天、跨周、跨月、闰年、时区（默认 `Asia/Shanghai`，可在设置里改）都由 `schedule.js` 的纯函数算，
**这部分不让模型算**——模型只负责把话翻成规则。

### 到点怎么判

- **精确 arm，不再盲轮询**：调度器取所有排期里最近的 `nextAt`，只在这个点醒来；
  封顶 5 分钟醒一次兜住「跨天 / 改设置 / 系统休眠」。
- **错过有策略**（设置里选）：
  - `delay`（默认）：宽限期（默认 30 分钟）内补跑一次；
  - `skip`：错过就跳过，等下个周期；
  - `next`：顺延到下一个窗口。
- **免打扰**：落在免打扰区间就顺延到结束，reason 会写明「免打扰推迟到 13:30」。
- **过点不开工**：任务截止时间已过，排期一律不触发。
- **显式排期不受三档总开关限制**：排期是「到这个点开工」的显式授权；总开关只决定
  「没被点名的新任务要不要自动开」。每轮仍受 `maxAutoStartPerRun` 限制，不会一次冒出一堆会话。
- **投递方式（delivery）三态**：

  | 取值 | 有会话 | 没会话 | 什么时候用 |
  | --- | --- | --- | --- |
  | `session`（默认） | 投进该会话 | 不触发，面板显示「未生效：还没有会话」 | 提醒、推进 |
  | `spawn` | 投进该会话 | 新建会话再投 | 飞书字段「按时执行」映射成它 |
  | `auto` | 投进该会话 | 新建会话再投 | 明确要「有就用、没有就建」 |

  没会话的 `session` 排期**在配置阶段就提示**，不会到点静默什么都不发生。
- **重复排期在开工之后不会停**：一次性排期跑完即失效；「每天 9:00 / 每周一」这类重复规则，
  任务开工后每到点**往已绑定的那条会话推一轮**（而不是每天新建一条会话）——
  一周七个孤儿会话是最容易踩的坑。
- **写回飞书**：默认把「下次触发时刻」写回任务原生的「开始时间」（`writeBackDefault`，可关），
  飞书侧、手机提醒里也看得见。

### AI 排今天：模型定顺序，插件算时间

`feishu_plan_today` 分两步，和洞察图表是同一个原则——**判断交给模型，算术留给本地**：

1. `action=preview`：插件返回候选池（优先级 / 截止 / 空闲天数 / 建议时长）+ 工作时段 + 容量；
   模型只回一个顺序：`[{taskId, minutes, why}]`。
2. `action=commit`：插件把顺序编译成真实时间块——跳过午休、不跨工作时段、超容量就报出哪条没排上，
   每个块落成一条一次性排期，可选同时写回飞书开始时间。

模型永远不用回答「15:00 加 90 分钟是几点几分」，也就不会算出 16:40 这种时间。

| --- | --- | --- |
| 时区 | Asia/Shanghai | 所有时间按它解释 |
| 工作时段 | 09:00-19:00 | AI 排期只往这段里放块 |
| 免打扰 | 12:00-13:30 | 到点顺延到结束 |
| 错过策略 | delay | delay / skip / next |
| 宽限分钟 | 30 | delay 的有效窗口 |
| 每日容量 | 360 分钟 | AI 排期总量上限 |
| 默认写回飞书 | 开 | 排期时同步任务开始时间 |

## 履约：预期完成时间

时间自动化解决「什么时候开始」，履约解决「答应的做没做到」。两者用同一套时间口径，
但履约的基准只有一个：**你亲口给的预期完成时间**。

### 三个时间，只有一个上卡片

| 时间 | 什么时候产生 | 卡片显示 | 去飞书 |
| --- | --- | --- | --- |
| 开始 | **绑定会话那一刻**（绑定即开工计时） | 不显示 | 原生「开始时间」+ 既有「开始时间」日期列 |
| 结束 | 标记完成那一刻 | 不显示 | 飞书原生完成时间 + 既有「结束时间」日期列 |
| **预期完成** | 你设置 / 改期 | **显示** | 「预期完成」文本列 |

开始/结束只用来算周期和履约，不占卡片；预期是承诺，必须一眼看见。

### 怎么设（自然语言，自动转固定格式）

- 卡片上点 `📅 设预期`，直接写人话，点「预览」会先显示转成的固定格式，再「保存」。
- 对话里说「这个周五前完成」「预期改到十月底」，模型调 `feishu_task_eta`。
- 往后改期会留一条**延期记录**，往前改（收紧承诺）不记延期；改期原因可以在工具里带 `reason`。

| 你写 | 转成（本地时区） |
| --- | --- |
| 这周五 / 明天 / 月底 / 下个月 5 号 | 当天 **18:00**（只给日期时默认下班前） |
| 下班前 / 上班前 / 中午前 | 今天（已过则明天）对应时刻 |
| 10-30 / 10-30 18:00 / 10/30 9:15 | 当年该日 |
| 2026-10-30 18:00 / ISO 时间 | 原样 |
| 截止前 2 小时 / 提前一天 | 相对任务截止时间 |
| 30 分钟后 / 半小时后 | 相对现在 |

不说时间点的（「每周一 9:30」「每天」）不会当成预期，会直接告诉你不合适；
完全看不懂的（「月底前」可以、「随便」不行）会给出候选让你补一句，不会瞎猜。

### 飞书字段：为什么是文本列

「预期完成」是清单自定义**文本**列，值固定 `YYYY-MM-DD HH:mm`。原因：飞书自定义「日期」列
只精确到天（实测写入 18:34 读回 00:00，UI 建的字段也一样），而履约要分钟。
代价是这一列不能按日期排序/筛选——这是已知取舍。详见
[DESIGN-task-lifecycle.md](docs/DESIGN-task-lifecycle.md) §10 的实测记录。

### 阈值与口径

- **准时 = 实际完成 ≤ 预期**；之后每改一次预期记一条「重承诺」，**不覆盖首次承诺**。
- 汇总同时给两个准时率：**严格口径**（首次承诺 vs 实际）和**最终口径**（最后一次承诺 vs 实际）。
  只改日期就能把延期洗成准时，所以严格口径才是主指标。
- 进行中且已过预期 = **逾期**（风险，不算延期）；完成时才结算。
- 指标：准时率、平均偏差、重承诺次数、逾期数、按工作区分组。全部本地算，进洞察卡的上下文。

### 写回开关

设置 → 时间自动化里三个开关（默认都开）：

| 开关 | 作用 | 失败时 |
| --- | --- | --- |
| 预期完成写回飞书 | 投影到「预期完成」列 | 进重试队列，面板标「未同步」，每轮同步补 5 条 |
| 绑定会话时写回开始时间 | 原生 start + 「开始时间」列 | 不回滚绑定，本地已有 startAt |
| 完成时写回结束时间 | 「结束时间」日期列 | 忽略，本地 endAt 已在 |

「开始时间/结束时间」两个日期列**只在清单里已存在时写**，不会自动创建；
「预期完成」文本列不存在时按需创建（每个清单一次，结果缓存）。

| --- | --- | --- |
| POST | `/api/tasks/eta` | `{taskId, action: preview\|set\|clear, when?, reason?}` |
| GET | `/api/fulfillment?days=28` | 履约汇总（纯本地） |

## 会话怎么感知任务

分四层，按「要不要花 token」切开，默认只开前两层：

| 层 | 触发 | 给会话什么 | 开关 |
| --- | --- | --- | --- |
| L1 开工档案 | 开工 / 自动开工 | 结构化「任务档案」：状态、负责人/关注人/创建人、开始截止、清单自定义字段、文档、任务链接 | 始终开 |
| L2 按需详情 | 模型主动调 `feishu_task_detail` | 上面全部 + **评论 / 子任务 / 附件** + 任务说明全文（120s 缓存） | 始终可用 |
| L3 绑定注入 | 绑定任务到会话时 | 往会话投一份任务档案 + 「要更多就用 feishu_task_detail」 | `contextInjection`，默认关 |
| L4 变化推送 | 同步发现标题/状态/新增文档变化 | 一行通知（同一会话 5 分钟最多一条，一轮同步最多一条） | `pushChanges`，默认关 |

几点取舍：

- **不在每轮注入全量**：任务档案走 L1/L3 一次性投递，之后要最新就调 L2；常驻的只有 L3 打开时那段几行的提示。
- **评论/子任务/附件是懒加载的**：这三样要额外打三次飞书接口（`/task/v2/comments`、`/task/v2/tasks/{guid}/subtasks`、`/task/v2/attachments`，都是资源型接口，路径写错会 404），所以只在调 `feishu_task_detail` 时拉，带 120s 缓存。
- **缺权限不炸**：没授 `task:comment:read` 这类 scope 时，详情里对应段落显示「（读取失败：…）」，其它字段照常。
- **评论人姓名**：评论的 creator 不一定是任务成员，第一次遇到会补查一次用户信息，查不到就退回显示 `ou_xxx`。

## 版本显示

插件版本并进状态条里 CLI 那个 chip：`v0.6.1 · CLI 0.3.1`——一行同时看到「插件哪一版 + CLI 什么状态」，
不额外占一行。版本来自宿主 `/api/state` 的 `version`（`package.json` 现读，不是写死的），
侧边栏同时开好几个插件时也能分清谁是谁。

## 任务过滤

列表头部的「筛选」按钮点开才展开过滤条（收起时只占一个按钮位），展开后**只有一行**；
有生效条件时按钮右边会挂一个小橙点，收起也知道自己筛过。条件记在 `localStorage`，刷新还留着：

| 控件 | 作用 |
| --- | --- |
| 工作区下拉 | 只留某个工作区的任务（选项从当前快照里出现过的值生成，不是写死的） |
| 状态 | 未完成（默认）/ 全部状态 / 已完成 |
| 关键词 | 按标题 + 描述做不区分大小写的包含匹配 |
| ✕ | 三个条件一起清空 |

计数会变成 `筛出数/总数`（例如 `2/7`），一眼知道筛掉了多少。工作区过滤对「没写工作区」的任务是排除的——
要连它们一起看就选「全部工作区」。

## Insight 卡片（早会视图）

任务列表上方一张卡，回答早会三问：**昨天做了什么、今天该做什么、哪里卡住了**。

| 分块 | 内容 | 成本 |
| --- | --- | --- |
| 一句话结论 | 💡 AI 给的当前推进状态（≤40 字）+ 一句「今天实际做了什么」 | 点「诊断」才调用 |
| 迷你图表（右栏） | 近 7 天完成（柱）· 近 14 天 WIP（折线）· 状态分布（环） | 打开面板就算，**收起状态也常驻** |
| 本地数据 | 全局分布（共 N / 在跑 / 未开始）+ 今日活跃/完成/新开工、完成度、偏离度、停滞与「开工两天没产出」 | 打开面板就绪，纯计算 |
| 今天做了什么 | 今日完成 + 有推进的任务（带「有进展评论 / N 篇文档」），顶部是 AI 的一句话 | 本地列表 0 token |
| 回顾与推荐 | 昨天完成/推进清单；今日按「延续 > 自动触发 > 停滞最久 > 编号小」排序并给理由 | 纯计算 |

- **诊断默认不自动跑**：打开面板只算本地指标；点「诊断」才调模型，结果按「日期 + 任务签名」落在
  `state.insight`，当天再打开直接复用。
- **输入只发摘要**：任务编号/标题/状态/工作区/空闲天数 + 每条会话最近回复的前 200 字；
  不发代码、不发完整对话。
- **履约材料也进诊断**（v0.12）：近 28 天准时率（首次承诺 / 最终承诺）、平均偏差、逾期与重承诺次数、
  提前/准时/延期分布、周期中位与 85 分位、延期原因分布（本地按关键词归成
  `dependency/scope/interrupt/estimate/environment/review/other` 七个桶）、最近 8 条延期记录、
  逾期未完成、承诺了但还没开工、近 7 天 vs 前 7 天的完成/开工趋势。
- **新增三块结论**：`fulfillmentComment`（一句履约判断）、`delayPatterns`（最多 3 类延期原因 + 每类的具体改法）、
  `improve`（2-3 条可执行改进）。**次数与涉及任务由本地回填**，模型只写「这类延期长什么样、下一轮怎么改」，
  写错桶名会被丢掉。
- **降级**：没模型时只剩本地数据块和「停卡片段」，不会假装有 AI 结论。
- **导出**：面板上的「写入任务评论」把早会摘要写成一条飞书任务评论（优先写当前会话绑定的任务）。

接口：`GET /api/insight`、`GET /api/insight/stats?days=14`、`POST /api/insight/diagnose`、`POST /api/insight/export`。

对话里也能诊断：工具 `feishu_insight`（`refresh` 先同步、`force` 忽略当天缓存），返回与面板同一份结论
（问题、履约判断、延期原因、改进建议），可以直接接着聊「那先改哪个」。

**布局**：顶栏只放「💡 今日洞察 + 按钮 + ⚙」（`nowrap` + 横向可滚动，按钮多了也不换行）；
统计信息挪到左侧文字块第一行；中间块左右各半、两栏等高——左边是多行结论（标题 + AI 判断/建议 +
三个分，或本地事实）+ 「展开」，右边**一张饼图，宽度至少 50%**；展开的清单横跨整宽。

**图表由 AI 选数据、形状固定为饼图**：诊断时模型返回 `charts:[{type,dataset,title,why}]`（`type` 支持
`bar/line/pie/sunburst`，卡片里统一按饼图渲染——一张卡塞三种图会淹没重点），
`dataset` 限五个本地数据集（近 7 天完成、近 7 天开工、近 14 天 WIP、状态分布、工作区分布）。
**数字永远来自本地**，模型只决定「用哪种图、展示哪份数据、标题怎么写」——既 AI 化，又不会出现编造的数值。

**触发**：点「诊断」强制重新生成；点「早会同步」或首次打开面板时，若当天还没有结论会自动生成一次
（结果按天缓存在 `state.insight`，同一天复用，不重复烧 token；改预期、加延期记录也算签名变化，
会重新诊断）。

**常见延期原因与对策**内置在提示词里（改预期估时、等依赖、需求变化、被打断、环境权限、返工验收），
模型按原因桶给具体做法，不说「提高效率」这种空话。提示词版本升级（`PROMPT_REV`）时，
设置里的自定义诊断 Prompt 会被新版默认替换——升级后建议看一眼是否需要重新追加你的偏好。

**数据落盘**：每日快照写进 `state.metricsByDay`，同时输出 `<DSH_HOME>/dsh-feishu/metrics.jsonl`
（一天一行，便于外部跟踪）。历史天数用任务时间戳回算，装上当天就有过去两周的形状。

**评估口径**见 [KNOWLEDGE-task-completion.md](docs/KNOWLEDGE-task-completion.md)：WIP / 周期中位数与 85 分位 /
切换税代理 / 完成偏好，全部只用本地可算的数据，不做心理推断、不做单点预测。

### 洞察设置（⚙）

卡片右上角的齿轮打开设置：

| 项 | 说明 |
| --- | --- |
| 诊断 Prompt | 可改；留空 = 用内置默认（`DEFAULT_INSIGHT_PROMPT`）。改完点「保存」才生效 |
| 按钮 | **可增删（最多 6 个），每个按钮可写自己的 Prompt**；按钮显示在卡片右上角 |

设置是**独立的一页**：点 ⚙ 后卡片内容整体让位给设置页（Prompt + 按钮列表），点「完成」回到内容页，
两者不会同屏。快捷键设置已去掉。

按钮有三种 `kind`：`morning`（本地早会视图）、`export`（写评论）、`ai`（用自己的 prompt 跑一次诊断）。
新增的按钮默认 `ai`；点它会带着自己的 prompt 请求 `/api/insight/diagnose`，缓存签名里带上 prompt 前缀，
所以不同按钮的结论互不覆盖。

快捷键的输入方式：点一下输入框，直接按组合键（例如 `Alt+Shift+M`），Esc 清除。
服务端会规范化并校验：只接受「至少一个修饰键 + 字母/数字」，认不出就退回默认值
（`alt+shift+M` / `alt+shift+D` / `alt+shift+E`）。

全局监听只在面板聚焦时生效，且焦点在输入框/文本域里时不拦截。

## 卡片主题色

**只有选中的那张卡显色**（描边 + 底色 + 呼吸光晕 + 徽标都跟着它自己的主题色），
其余卡片保持中性描边——一列卡片的边框五颜六色会把「选中」这件事本身淹掉。

颜色由**任务编号**算出来：

```
hue = (no × 137.508°) mod 360      // 黄金角散开，相邻编号颜色差得远，几十条内不撞色
```

编号是持久的（`state.numbers`），所以同一个任务的颜色不会因为刷新、改标题、换端口而变。

徽标用同色系淡染而不是纯色底：浅色相（比如黄绿）配白字会糊。
未选中的卡片不带任何色条／色边。

## 当前对话的卡片

面板会拿到宿主推来的「当前会话 id」（`postMessage: dsh-feishu:context`），把它绑定的那张任务卡单独标出来：

- 描边换成**橙色**（`--p-select`，浅色 `#ea6a12` / 深色 `#ff9f45`），带 2s 呼吸动画（`task-current-pulse`）
- **底色也换**：橙色自上而下淡出（`linear-gradient(var(--p-select-weak), transparent 72%)`）压在卡片底色上，
  和一堆白卡拉开距离，正文对比度不受影响
- 「当前对话」徽标是橙底白字，不跟强调蓝混在一起
- **自动置顶**：这条任务卡永远排在列表第一位（只换顺序，不改快照；
  其余任务之间的相对顺序保持不变），翻面板时第一眼就是「我现在在干的这条」
- 标题行右侧多一个「当前对话」徽标
- `prefers-reduced-motion` 下保留描边、关掉动画

没绑定任务时不会高亮——那种情况下第一张卡是「当前会话 → 同步为飞书任务」的入口。

## 进展自动写回评论

绑定了任务的会话，**有实际进展的 turn 结束**时，把这一轮干了什么写进飞书任务评论。

- **触发点**：宿主 `session/event` 的 `turn/end`（一轮 = 一个 turn，模型吐多段也只写一条）。
- **只在有硬证据时写**：这一轮**改了文件**（`write`/`edit` 类工具带 `file_path`）、**产生了 commit**
  （命令里有 `git commit`，或正文提到「提交/commit」并带短码）、**跑了测试**（命令里有 test/pytest/jest/vitest）。
  只是聊了两句的轮次不写——评论列表才不会变成噪音。
- **格式**：`🤖 AI 进度 · 21:20` 开头，正文用第一人称（「我改了 2 个文件：…」「我提交了 commit：5d2d362」
  「我跑了测试：node test/meta.mjs」），末尾附一句本轮结论（≤240 字），整体 ≤700 字。
- **频率**：同一会话两条之间至少隔 `autoCommentMinSeconds`（默认 45 秒，面板可调 10–3600）。
- **失败**：写失败只记 warn，并挂进内存队列，下一次 turn 结束补发一次，不做无限重试。
- **开关**：`autoComment`（默认开）。

> 一句话取舍：这里刻意不调模型做二次摘要——每个 turn 多花一次模型调用既慢又贵；
> 直接裁切助手文本已经能让同事看懂「这一轮做了什么」。

## 从会话回写飞书

任务面板里的**第一张卡**是「当前会话」卡，只在**这条会话还没绑定任何飞书任务**时出现：

```
会话未绑定任务  →  显示「当前会话」卡 + 「同步为飞书任务」按钮
点这个按钮      →  宿主读会话记录里最后一条助手回复，清洗掉代码围栏
                   派生标题（首行，≤30 字）+ 描述（前 2000 字，坏链已降级为文字），用 CLI 建任务
创建成功        →  自动加进你那个清单（add_tasklist）并绑定会话；这张卡消失，新任务以普通任务卡出现
先点「开工」    →  会话被绑定；这张卡同样消失
```

也就是说：这张卡是「还没有任务的会话」的入口，一旦会话有了归属任务，它就退场，不会和普通任务卡重复。

另外两条回写路径仍然在：

- **模型**：让 agent「把结论同步到飞书任务」，调 `feishu_task_report`（默认取当前会话绑定的任务）。
- **快速完成**：任务卡会话行的 `✓`，只把任务置完成、不写评论。

## 文档

任务上的文档用清单自定义字段承载（字段名默认「文档」，可在 `settings.taskFields.doc` 改），
卡片里是一行可操作的 chip，不只是一串链接：

| 动作 | 在哪 | 落到哪儿 |
| --- | --- | --- |
| 绑定 | 还没绑文档时卡片文档行有「＋ 文档」→ 贴链接 → 回车/绑定 | 本地记一条 `手动` 文档 + **立刻**把链接写回飞书「文档」字段（一行一个） |
| 解绑 | chip 右侧的 `✕` | 从本地移除 + 同步重写飞书字段；飞书里的文档本身不删 |
| 改链接 | chip 右侧的 `✎` | 换成另一篇文档：标题按新链接重新问一次，并重写飞书「文档」字段 |
| 生成 / 更新 | 卡片上的「生成文档 / 更新文档」 | 在 `DSH 任务文档 / <T<n>-任务名> / <任务名>.docx` 落一篇，链接同样写回「文档」字段 |
| 改名联动 | 双击任务标题改名 | 任务名变了，**它自己生成的那篇文档**的标题也跟着改成新任务名（手动绑定的外部文档不动） |

几条实现上的取舍：

- **一条任务一篇文档**：已经绑了文档就不显示「＋ 文档」，换/删走 chip 上的 `✎` / `✕`，避免卡片上堆一串入口。
- **会话能感知文档**：开工投递的提示词里有「文档：」一段（`{{docs}}` 占位符；
  老的自定义模板没写这个占位符时，文档会追加在提示词末尾，不改你的措辞），
  模型工具 `feishu_tasks` 的输出也带每条任务已绑定的文档链接；要读正文再调 `feishu_doc_read`。
- **绑定即同步**：`bindTaskDoc()` 写完本地马上 `pushDocField()`，不用等人再点一次「同步」；
  面板的 toast 会明确说是「已绑定并写回飞书」还是「已绑定但写回失败：原因」，失败不假装成功。
- **任务改名联动用的接口**：docx 没有「更新标题」的开放接口，Drive 的改名又要 `docx:document:write_only`
  （个人令牌通常没授这个 scope）。所以改的是 docx 的**页面块**（root block，`block_id == document_id`）的
  text——它就是文档标题，权限只要 `docx:document` 写，实测改完 `GET /docx/v1/documents/{id}` 的 title 立即变。
- **字段里只有链接时补标题**：别人的任务字段里可能只有一个 docx 链接。同步时按 URL 去问一次 `info_page`，
  结果进 `state.docTitles` 缓存（问过没拿到就记 `null`，不会每轮重试），每轮最多补 3 篇。
- **识别**：从任务描述里抽 `docx / docs / wiki / sheets / base` 链接，和本地文档一起按 URL 去重展示。
- **渲染限制**：飞书 docx 的文本块不解析 Markdown，表格和 Mermaid 目前是**原样文本**（管道表格 / mermaid 代码）。
  要真正渲染成表格需要用 docx 表格块逐格创建，Mermaid 需要先渲染成图片再插入——这两步还没做。

## 会话跳转

点任务标题后的会话 id（`● feishu-xxx…`）会跳到那条对话：面板 `postMessage` 给宿主，
client 半体调 `uiWorkspace.openSession(sessionId)`，并把结果回传给面板。

**已绑定的卡可以直接「换绑」**：绑错了一条只能解绑再绑太绕，现在卡上有「换绑」按钮
（只有当前会话不是它绑的那条时才出现），点一下就把当前对话换成它绑定的会话。

**会核对结果**：`openSession` 是「尽力而为」的，宿主解析不到时不一定抛错，而是把主视图切到它以为对的那条上
（表现就是「点 A 跳到 B」）。所以调用后隔一帧读回 `uiWorkspace.selection` 里的 `sessionId`，
和目标不一致就把「实际切到了 xxx」报回面板——至少不会静默跑偏。
读不到 `selection` 时退回**窗口标题**核对（会话名默认 = 任务名），标题对不上也会报出来。

当前已收紧的三条：当前对话那张卡点了只提示「这就是当前对话」；已结束的会话改成复制 ID；
回执发给发消息的那个窗口（以前重新 `querySelector` iframe，查空就静默丢回执）。

注意 client 半体是宿主启动时打包的，改了之后需要重载插件（或重启宿主）才生效。

## 任务名：双击改名 + AI 起名

- 任务卡上的开工按钮就叫「开工」，不跟括号说明；当前会话能不能复用由 tooltip 和结果提示表达。
- 卡片只有两个入口，且**只在还没绑会话时出现**：**开工**（开一条会话干活，当前有会话就绑到当前这条）
  和 **绑定**（只把当前会话绑到任务并同步名称，不投递、不开工）。
  已经绑了会话的卡**不再显示「开工」**——绑定即视为已开工，动作行只剩 完成 / 删除 / 解绑 / 同步 / 生成文档。
- 会话行三个动作都真的落到飞书/D SH 上：**完成**＝飞书任务置 done + 归档会话；**删除**＝归档（删除）这条会话、
  任务状态不变；**解绑**＝只清任务↔会话关系（任务回到未开工）。复制按钮已去掉。
- **双击任务标题**进入就地编辑：`Enter` 或「保存」按钮提交，`Esc` 或失焦放弃（失焦不自动保存：点 AI 按钮会抢焦点，
  实测会用旧值把新标题盖掉）。
- 编辑框右侧有「AI 起名」：调 `POST /api/tasks/suggest-title`，把任务标题 + 描述 + 绑定会话最后一条回复
  交给默认模型，按「正式任务名」的提示词生成（12-20 字、动宾结构、书面语、不带标点/人称）。
  **生成即写回飞书**（`tasks/rename`），toast 里带上原标题方便对照——以前只填进输入框、还要再按回车，
  容易被当成「没生效」。模型没给出可用标题时只填草稿，绝不自动改。
  AI 失败时提示里会带原因，不会假装成功。
  注意推理型模型（如 deepseek-v4.1-flash-tencent）会先把 token 花在 reasoning 上：200 的额度能全被推理吃掉、
  一个文本块都不吐。所以标题调用给了 600/1600 两档预算并在空结果时重试，同时兼容 `text-delta` 与 `block-end` 两种取文本方式。
- **命名只有一处出口**：`buildTaskTitle()`（表情 + 编号）。创建（「同步为飞书任务」）、AI 起名、
  改名全部走它——以前创建那条链路自己拼编号、漏了表情，同一个产品里两种名字观感不一致。
- **任务名格式**：`<表情> T<n>-<标题>`（表情最前，扫一眼先看类型）。`n` 按任务首次出现的顺序稳定分配（存在 state 里，不随同步变化），
  新建任务、AI 起名、手动改名都会补这个前缀；旧标题里的 `Task-xxxxxx` 短码会被清掉。
- **表情前缀**：AI 起名时按「标题 + 任务材料」挑一个表情放在名字前面，方便在列表里一眼分类型——
  🐛 修复 / 🧪 测试联调 / 📄 文档 / 🎮 游戏场景 / 📊 数据指标 / 🔍 排查 / 🚀 发布 / 🔧 重构 / ✨ 新增功能。
  挑不到就按标题哈希落在一个固定集合里（📌🗂️🧩🛠️📎🎯）：同一个标题永远同一个表情，不会每次刷新都变；
  重复起名会先摘掉旧表情再加，不会叠成一串；手动改名沿用原来的表情（自己打了表情就以你打的为准）。
- **专有名词原样保留**：AI 起名时产品/框架/协议/快捷键/接口名（Ctrl+P、Feishu、DSH、Cordis、MCP…）
  不改写、不意译、不泛化。
- 保存走 `POST /api/tasks/rename`：`feishu-sync-cli task update --summary` 改飞书标题 → 更新本地状态 →
  会话还活着就同步改会话名（任务名 = 会话名）。

## 任务名 = 会话名

- **任务 → 会话**：开工（新建会话，或绑定已有会话）时把会话标题改成任务标题；面板上双击改名 / AI 起名后保存、
  以及建任务时，也都会同步改会话名。改名有两条路：会话活着走 `sessionTitle.rename()`（写 user 来源标题事件、钉住），
  会话已归档走 `sessionController.rename({sessionId,title})`（不需要先把 agent 拉起来）。
- **会话 → 任务**：面板上「同步为飞书任务」时，先用 `llm.stream`（purpose: `session-title`）让当前默认模型起一个
  ≤18 字的任务名，失败才回退到「首行 30 字」；建任务后再把这条会话改名成同一个标题（会话没激活就跳过改名，只建任务）。
- 实测：开工后会话标题事件变成 `{"title":"命名对齐验证3（可删）","source":{"kind":"user"}}`，且后续自动标题不再覆盖。

## 身份对应关系（会话 ↔ 任务 ↔ 编号）

三个 id 各管一段，边界都写在代码里：

| 东西 | 存在哪 | 掉了会怎样 | 兜底 |
| --- | --- | --- | --- |
| 任务 | 飞书任务 guid | 任务被删 → 本地同步就没了 | — |
| 编号 `T<n>` | `state.numbers[taskId]` | 任务被过滤掉（关键词/只看未完成/归档）再回来，重新编号 → 撞号、标题被改写 | 编号表：回来时优先拿回原号；`repairTitleNumbers` 只修「编号 ≠ no」的 |
| 绑定 | `state.bindings[taskId]` | 同上：任务暂时掉出列表，绑定跟着丢 → 卡片变「未开工」，再点又开一条新会话 | 绑定快照：回来时按 id 接回会话 |
| 状态文件 | `<DSH_HOME>/dsh-feishu/state.json`（**全 DSH_HOME 一份**） | 以前按端口分文件，换端口靠「猜最新那份」继承 → 同一任务被两条实例各开一条会话 | 单文件 + 首次启动从最新旧文件迁移一次 |

### 统一任务命名

设置区底部的「统一任务命名」把**已有**任务名规整成同一规则（表情 + `T<n>-` + 标题）：
漏表情的补上、编号和 `no` 不符的改正。只改「算出来和现在不一样」的，可以反复点。

> 它只改任务标题，不动会话名；要会话名也跟着改，双击标题回车走一次改名即可。

### 已完成任务重新开工

恢复归档会话本身不会改变飞书任务状态。原绑定会话产生新的 `turn/start`（确实重新执行）后，插件将同一条已完成任务重开为未完成，并只写回飞书 `completed_at=0`；不新建任务、不改变绑定、不恢复旧定时。挂起任务不会自动重开。

重开先持久化本地意图，写回失败保留待同步状态，并在后续同步中有界重试；远端旧的完成回声不能覆盖重开。原完成时间保存在有界历史里，当前完成/结束时间清空；重新完成时以新的完成时间结算。插件重新加载时仅对已有活跃、且开工晚于完成时间的会话补对账，不主动唤醒会话。

### AI 评论标识

新 AI 评论统一使用 `[🤖AI 回复]` 身份行及上下 `--------------------` 分隔线；只清除开头重复的机器人/AI 标识，不改正文风格。格式在出站账本落盘前固定，失败重试仍使用同一份内容，不改旧评论或待重试内容。插件评论区把标识放在作者旁，正文去掉重复外框；真实提及通道不再额外添加机器人前缀。当前仍使用既有个人授权身份，未切换到缺少任务权限的应用机器人。

### 实时会话状态

运行灯、优先级光圈、未读点和运行柱通过同源 `/api/sessions/activity` 事件流接收 DSH 状态，不等待飞书同步。流先给轻量会话基线，再由运行状态和 turn 开始/结束事件触发更新；只更新指示器，不重建任务卡，不打断输入和浮层。断线后重连基线，隐藏页面关闭流，低频任务快照仍作兜底。事件流不读写飞书、不激活会话、不变更绑定或定时。

### 孤儿会话清理

设置区底部有「清理孤儿会话」：扫描 `feishu-` 前缀、但没有任何任务（含绑定快照）指向的会话，
列出来让你确认后批量归档。归档过的 id 记进 `state.archivedOrphans`，不会反复冒出来
（归档只是移入归档集，目录不删）。

已知限制：

- 两个 DSH 实例**同时**跑在同一份 `state.json` 上时，写是全量覆盖（最后写的赢）。
  绑定/编号有快照兜底，但极端时序下仍可能丢一次更新；长期建议只跑一个实例。
- 会话被归档/删除后，任务上的 `sessionId` 仍然保留（卡片显示「已结束」，点 chip 只能复制 ID）。
  想彻底断开用「解绑」。

## 任务与会话的对应关系

每条任务最多绑一条会话，每条会话也只会属于一条任务（`linkTask` 会拒绝重复占用）。绑定信息存在
`state.json` 的 `sessionId / startedAt / linkSource` 里；`sessionAlive` 是快照时现算的，只看本进程里
agent 是否还在跑，不代表会话被删了。面板上的「打开会话」通过 client 半体调宿主 `uiWorkspace.openSession`，
所以它切的是右侧栏外的会话视图，不是新开窗口。

## 数据落在哪

- `~/.dsh/dsh-feishu/settings.json`：面板里保存的设置。
- `~/.dsh/dsh-feishu/state-<端口>.json`：同步快照（任务、文档、授权状态、上次同步时间）。
  按端口分文件是因为同一台机器可能同时跑两个 profile 的宿主，共用一个文件会互相覆盖刚绑好的会话。
  **换端口重启不丢状态**：本端口文件还是空的时，会继承同目录里最新一份带会话绑定的 `state-*.json`
  （DSH 每次重启会换端口，不继承的话表现就是「任务卡片集体掉绑定 + 自动开工又开一条新会话」）。
- 飞书令牌仍然只在 `~/.feishu/`，由 CLI 管理，插件不读不写。

## 手动核对

```bash
npm test              # 客户端半体单测 + 宿主半体冒烟（真实读一次飞书任务）
npm run test:client   # 只跑客户端半体：假 ModuleLoader/React/ctx，验注册口
npm run test:smoke    # 只跑宿主半体：假 ctx 起路由，真跑一次同步
```

- `test/client.mjs` 验的是**注册口**：模块必须通过 `__ModuleLoader__.load` 注册、
  `inject` 里有 `betterSidebar`、`registerTab` 收到 `{id:'feishu', component, icon, single}`，
  以及 `betterSidebar` 缺席时 `apply()` 不抛（抛了会把宿主打成错误页）。
- `test/smoke.mjs` 验宿主：路由挂载、`/api/state` 形状、真实同步、设置写入与未知字段过滤、
  开工（用假 `agents`/`sessionController` 抓建会话参数和投递内容）、工具注册。
- 两个脚本都用 `DSH_HOME=/tmp/dsh-feishu-smoke` 隔离设置文件，不会污染你的配置。

## 权限与安全

- `feishu_task_comment` 是**写操作**，会真的发到飞书。其余工具只读。
- HTTP 路由挂在宿主 webServer 的 `/dsh-feishu` 前缀下，与其它插件同域；没有额外的鉴权层，靠宿主本身只监听 localhost。
- 自动开工会在你的默认工作目录里建会话并立刻跑一轮，**会消耗 token**；默认关闭。
