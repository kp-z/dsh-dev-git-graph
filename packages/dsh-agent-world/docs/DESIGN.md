# 视觉与前端结构规范（R32 起）

> 用户要求："前端场景和各个模块设计得好看一点，现代一点"，并且"重新整理代码"。
> 这份文档是**两条并行工作线共同遵守的规范**——一条改场景（内容皮肤 + 3D），一条改面板（结构 + 样式）。
> 它们写不同的文件，但必须对着同一套设计 token，否则拼起来会像两个产品。

## 零、出发点：亲眼看过的现状（R32 截图 + 视觉评审）

最影响现代感的五个问题，按严重程度：

1. **场景配色脏**：地块是土黄 `#6F7D5A`、灰蓝 `#5C6B78`、土褐 `#8A7A5C`——低饱和、低明度，像过期的平面图。
   而场景是整个产品的**舞台**。
2. **没有留白与层级**：面板之间只靠 1px 细边框区分，没有阴影、没有间距节奏；所有列表行距过密。
3. **组件像浏览器默认样式**：按钮、列表、图例都没设计过；图例像调试遗留物。
4. **状态只有文字**：进度"60%"没有进度条，状态"进行中"没有徽章。
5. **字号层级扁平**：标题与正文几乎一样大。

另外布局上：**场景被挤压**（右侧栏 + 底部看板占了太多），看板占屏幕下 1/3，视觉重心下移。

## 一、设计方向（一句话）

**"夜间工作室里的玻璃控制台"**：深色基底，**场景是发光的主角**，面板是**半透明玻璃浮在场景之上**，
信息用**徽章、进度条、胶囊**表达，而不是文字堆。

参照系：Linear / Vercel 的深色控制台（层级与留白）+ 等距小镇游戏（场景的暖色与可爱感）。

## 二、设计 token（**唯一来源**，两条线都只用它们）

所有颜色、圆角、阴影、间距都以 CSS 变量给出，定义在 `web/styles/tokens.css`。
**任何组件样式里不许出现十六进制颜色字面量**（场景配色走内容库 `skins`，见第四节）。

## 三、布局（场景为主角）

```
┌─────────────────────────────────────────────────────────────────┐
│ ◉ Agent World   [俯视|3D]   ● 运行中 tick 1234        ⏸  ▶     │  顶栏：玻璃、56px、单行
├─────────────────────────────────────────────────────────────────┤
│                                                     ┌─────────┐ │
│                                                     │ 花名册   │ │
│              场景（铺满整个工作区）                   │ 8 张卡片 │ │  右侧：浮动玻璃抽屉
│                                                     ├─────────┤ │  （可收起，宽 320px）
│                                                     │ 工单     │ │
│   ┌ 图例（左下角小胶囊，可收起）┐                     │ 进度条   │ │
│   └──────────────────────────┘                      └─────────┘ │
│      ┌──────────── 执行看板（底部抽屉，默认收起成一条摘要）────────────┐ │
│      │ 3 进行中 · 6 待办 · 1 完成   ████████░░░░   ▲ 展开          │ │
│      └──────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────┘
```

- **场景铺满工作区**，面板是**浮在它上面的玻璃**，而不是把它挤小。
- 右侧抽屉与底部看板都**可收起**；底部看板**默认收起成一条摘要**（计数 + 进度条），点开才是完整依赖图。
- 对话面板从右侧滑出，覆盖在花名册之上（同一个抽屉的另一个"页"）。

## 四、场景配色走内容，不走代码（D31/D37 的延续）

场景的地块、站点、角色色全部来自内容库 `skins`。这一轮**新增一套皮肤** `skin.nightfall`（夜色工作室），
并在默认场景里选用它；旧的 `skin.default` 保留，换回去只是改一个 id。

设计要点：
- 地面：深蓝灰基底 + **每个地块一个有辨识度但不刺眼**的色相（工程=青、机房=靛、会议=紫、公共=暖橙），
  明度比背景高一档，让地块像被灯照亮的台面；
- 站点：比所在地块再亮一档，带细描边；
- 角色：保持高饱和（它们是画面里最小、最需要被看见的东西）；
- 3D：主光偏冷白、补光偏暖，开 ACES 色调映射；地面加一层很淡的网格线增加"工作台"质感。

**为什么这一条重要**：它是 R16 那句"换皮肤 = 改内容、零代码改动"的第一次大规模兑现。
验收时要能说出：**`src/sim|domain|protocol|routes` 一行没改，场景就换了一个样子。**

## 五、代码结构（`web/` 重组）

现状是 8 个扁平文件 4434 行，`app.js` 854 行同时管连接、状态、渲染接线、对话、看板。重组为：

```
web/
  index.html
  main.js                    入口：只做装配（原 app.js 的组合根部分）
  core/                      纯逻辑，不碰 DOM，全部可被 node 测
    world-update.js
    dialogue-state.js
    board-layout.js
  net/
    connection.js            快照 + SSE + 重连（从 app.js 抽出）
  scene/
    scene2d.js               俯视图渲染（从 app.js 抽出）
    scene3d.js
    builders.js
    model-loader.js
  ui/
    topbar.js  roster.js  tasks.js  legend.js  drawer.js
    dialogue-ui.js
    board.js
  styles/
    tokens.css               设计 token（第二节）
    base.css                 reset、排版
    components.css           按钮、徽章、进度条、卡片、胶囊
    layout.css               顶栏、抽屉、浮层
```

**规矩**：
- `core/` 里不许碰 DOM、不许读时钟（同 `world-update.js` 现在的做法）——它们是可测的那部分；
- `main.js` 只装配，不写业务；
- 移动文件时**测试的 import 路径跟着改**，`test/boundaries.test.js` 的 web 规则（只许 import protocol）仍然成立；
- `scripts/copy-web.mjs` 是递归复制，子目录无需改构建。

## 六、验收（两条线都要过）

1. `typecheck` + `pnpm test` 全绿；
2. **亲眼看**：俯视、3D 两个视图各一张截图，交给视觉评审，回答第零节那五个问题是否解决；
3. `?debug=1` → `__agentWorldBoard.clipped()` 在 1280/1024/800 三个宽度下为空（M7-9 的检查不许退化）；
4. 3D `benchmark(120)` 不劣于 R21 基线 0.35ms；状态栏 `重建` 停在 1（`backdrop-filter` 有 GPU 成本，必须量）；
5. 功能不回退：点角色能开对话、看板能选中任务、暂停/继续可用。
