## 二、问题清单（按"对观感的伤害"排序，每条都有依据）

### P0 —— 三个角色站在沙发里（一眼可见的穿模，已量化）
沙发是 `station.breakroom`，落在 `(5.5, 3.0)`。八个角色的歇脚点由 `1.6/4/6.4` 的**网格硬摊**，
没有人把家具的占位算进去。算距离（真机坐标）：

| 角色 | 到沙发中心 | |
|---|---|---|
| 小青 | **1.35** | 在沙发里 |
| 小铁 | **1.66** | 在沙发里 |
| 小紫 | **1.80** | 在沙发里 |
| 小蓝 | 2.05 | 贴着边 |

**根因**：`hangout` 是**布局层按网格分配**的（`world/create.ts`），它不认识家具；
而家具位置由场景内容决定。两者各算各的，必然重叠。
**判据**：角色与家具包围盒的距离要有下限（不重叠）；角色之间也要有下限。**两者都要能被算出来**（纯函数 + 测试）。

### P0 —— 工位上是空桌子，人坐在空气里
`station.desk-a/b/c` 与评审桌都引用同一个 `model.station.desk`（**一张光桌子**）。
已 vendor 的 `chair.glb` / `chairDesk.glb` / `computerScreen.glb` / `keyboard.glb` 等**全都没有消费者**。
M4-11 已经把这个需求写下来了（`SceneProp.modelId` 是单数，所以"桌 + 椅 + 显示器"摆不出来），但**还没做**。
**判据**：工位至少有桌椅；`computerScreen` 之类的桌面道具摆上去。

### P1 —— 8 个人长得一模一样
12 个 Kenney 角色模型都在库里，但 8 个角色全用同一个 `model.agent.base`。
**判据**：内容侧能声明"这一组角色按序用这几个模型"（BACKLOG 里已有此条），截图里能看出不同的人。

### P1 —— 地面几乎全黑，只有公共区有颜色
截图里工程区/机房/会议区的地面几乎是黑的，只有公共区（棕）有存在感；
分区之间的**边界只有一条细线**，看不出"这是哪一区"。
**判据**：四个区各自可辨（地面色差或边界线），并有一处光源/明暗对比让立体感成立。

### P2 —— 场景四周是纯黑虚空
`groundSize` 之外没有任何东西（没有远景、没有天空盒、没有地面延伸）。
当前"纸感等距"主题（`post.bloom.enabled: false`）下这是可接受的极简，但**规模一大就会显得像漂浮的孤岛**。
**判据**：要么明确"极简就是设计"，要么给一圈围栏/远景。**这条要用户拍板**。

### P2 —— 角色没有动作（`actions` 库没有被消费）
人站着不动（`idle`），`actions` 库与 32 条剪辑至今无人消费（M5-2 一直没做，优先级被 M6 系列压后）。
**判据**：`walking` 时至少有位移之外的动作表现（走路的姿态或摆动）。

## 三、建议的动手顺序

1. **P0 两条先修**：它们是一眼可见的错误（穿模、空桌子），而且**都不需要新资产**——椅子/显示器已经在库里。
   修法上 P0-1 是**布局算法**（歇脚点要避开家具占位，属于机制），P0-2 是**内容**（站点声明多个模型，M4-11 已设计好）。
2. 然后 P1 两条（角色区分、分区可辨）。
3. P2 两条等用户拍板（是否接受"极简孤岛"的观感；动作库接上动画是另一笔较大的活）。

**注意**：M4-12（纹理泄漏）正在被修（R47 task-10）。它是**规模问题**，修完之前不适合做"摆更多模型"的改动——
否则泄漏会随道具数量放大。
