# 图集逐格索引（2D 像素资源）

> **为什么需要这份表**：R50 收的 11 个像素包**没有一份逐格名称表**（它们只给整张图集 + 作者示例场景）。
> 所以"哪一格是草地、哪一格是桌子"**只能由人标注**。不标注就去接渲染，只能靠眼睛认，
> 而认错的表现是"地砖没问题、但家具是另一件东西"——极难归因。
>
> **本表的规矩**：每条都给**可复算的依据**（平均色、不透明像素数、实测尺寸），不写"看起来像"。
> 凡是**我没有可靠依据**的格子，就不写进表里——**宁可留空也不猜**（见文末"还没标注的"）。

## 一、量法

```bash
# 平均色与不透明像素数（判"这是不是一块满铺地砖"）
python3 -c "
from PIL import Image
im = Image.open('…/tile_0043.png').convert('RGBA')
px = [q for q in im.getdata() if q[3] > 200]
print(len(px), tuple(round(sum(q[i] for q in px)/len(px)) for i in range(3)))"
```

判据：**不透明像素 = 256**（16×16 全铺满）+ **颜色数 ≤ 3** ⇒ 这是一块可重复平铺的**地面砖**。
不满足的（边缘透明、色数多）是**物体**（家具/植物/建筑），它们的位置依赖场景，另表处理。

## 三、人物（实测尺寸，唯一带走路帧的来源）

| 文件 | 实测 | 切法 |
|---|---|---|
| `characters/oga-16x16-base-sprites/base_male.png` | **126×144** | `cellW=18, cellH=18, rowsPerFigure=2`（一格 18×18，人物 18 宽 × 36 高，跨 2 行） |
| `characters/oga-16x16-base-sprites/base_female.png` | **126×144** | 同上 |
| `characters/oga-16x16-base-sprites/walk_cycle_{male,female}.gif` | 24 帧，每帧 **18×36**，`duration=150ms` | **24 = 4 方向 × 6 帧** |

**7 列 × 8 行 = 4 条带**（每条带 2 行高 ⇒ 4 个方向），每条带 7 列里有 6 帧是行走、第 7 格是重复首帧。
**方向顺序**：由像素计数交叉验证——行 0/1 与行 2/3 **逐格计数完全相同**
（`166 153 152 166 153 152 166` vs `148 154 141 144 154 141 144`），
说明是"同一批姿势的两组"（前/后 与 左/右）；再结合作者示例与常见约定，顺序为
**下 → 上 → 左 → 右**。⚠️ **这一条我没有找到作者的文字说明**，属于"由计数 + 惯例推出"，
所以接入时**要肉眼核对一次**（渲染出来四个方向对不对，一秒就能看出来）。

调色板（实测，不透明像素数）：`#FFE6E2`（2816 px，皮肤）、`#D6A1B2`（1920 px，中间调）、
`#996B88`（2238 px，深色）、外加 4 个各 28 px 的点缀色（`#0F0814` `#314829` `#FFFFFF` `#B5EE2D`）。
**重上色只动那 3 个主色，点缀色原样保留**——否则眼睛/工具那种小色块会跟着变。

## 五、下一步怎么把第四节补上

1. **做小批量拼贴而不是整张大图**：视觉模型认不了 132 格的编号，但**认得了 4~6 格一行**。
   按 6 格一批出图、每批问"这 6 格分别是什么"，是可行且可复核的。
2. 或者**用作者自带的 `Sample.png`**（每个包都有）——它展示的是"这些格子按作者的意图拼起来长什么样"，
   把示例里的物件与图集格子对上，比凭空认更快。
3. 标注结果**追加到本表**，一格一条，依据写"与 Sample 里第 N 个物件对应"。
