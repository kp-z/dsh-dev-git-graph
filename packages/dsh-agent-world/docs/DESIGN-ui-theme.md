## 一、诊断：不是色值，是语言

Lead 的诊断我复核后确认，并补一条**量化证据**（见 §3.3）。核心矛盾：

| 现状（`web/styles/*.css`） | 游戏本身 |
|---|---|
| 36 处 `border-radius`（`--r-sm:6 / --r-md:10 / --r-lg:16 / --r-pill:999`） | 16px 像素图，**硬边零圆角** |
| 18 处模糊阴影（`0 8px 32px`） | 像素画没有柔和投影，只有**硬偏移** |
| 10 处 `backdrop-filter: blur(16px) saturate(140%)` | **无模糊** |
| `--glass: rgba(58,58,80,.78)` 玻璃面板 | **米色 9-slice 实体面板** `#D3BF8F`/`#B1A077` |

⇒ 一套**现代 Web 的"半透明毛玻璃"语言**，贴在一张**硬边像素画**上。这是审美的断层，不是色号的偏差。

> `tokens.css` R57 那段"配色从美术出发"没错——`#3A3A50` 确实是从家具量出来的。
> 问题是这套色被装进了**玻璃+模糊+大圆角**的容器里。本轮换容器，不换血缘。

## 二、采样（每一项的来源）

所有值都是**实测**，不是取色器目测。命令与坐标可复现。

### 2.1 采样方法

```bash

    print(px, f'{n*100/(im.size[0]*im.size[1]):.1f}%')
PY
```

### 2.2 9-slice 面板：`Ancient/tan.png`（48×48）

逐行/逐列读取证实：**这是一圈 2px 描边套实心内芯**，正是像素 UI 的"斜角描边"语言。

| 位置 | 色值 | 占比 | 角色 |
|---|---|---|---|
| `y0` 整行 / `x0` 整列 | `#D9CDAF` | 7.8% | **外描边（亮）** |
| `y1` 整行 / `x1` 整列 | `#B1A077` | 8.4% | **内描边（暗）** |
| 内芯（`y≥2 && x≥2`） | `#D3BF8F` | 79.5% | **面板底色（主）** |
| 四角 | `#A3997F` | 4.2% | 角落过渡（**本轮不用**，CSS 无法在 0 圆角下画出单像素角） |

> **关键的形状发现**：描边是 **2px 双层**（外亮 `#D9CDAF` + 内暗 `#B1A077`），不是单线。
> 这就是"像素描边"能被肉眼读成描边的原理——用**一亮一暗**造出微浮雕。
> CSS 里对应 `border: 1px solid #B1A077` + `box-shadow: inset 0 0 0 1px #D9CDAF`（**0 模糊**）。

其余三色同构（取众数）：

| 文件 | 内芯 | 内描边 | 外描边 |
|---|---|---|---|
| `tan.png` | `#D3BF8F` | `#B1A077` | `#D9CDAF` |
| `white.png` | `#E5E5E5` | `#CBCBCB` | `#E9E9E9` |
| `brown.png` | `#97714A` | `#886644` | `#B7916A` |
| `grey.png` | `#838796` | `#727685` | `#9B9DAD` |
| `white_inlay.png` | `#ECE3CE` | —（纯色 99.1%） | — |

⇒ **`white_inlay` 的 `#ECE3CE` 是"纸"**：比 `tan` 内芯更亮、更中性，适合做**卡内的浅色内容区**。

## 三、语言三条（本轮要换掉的东西）

### 3.1 形状：圆角 0，双层描边，硬偏移阴影

| 项 | 旧 | 新 | 理由 |
|---|---|---|---|
| 圆角 | `--r-sm:6 --r-md:10 --r-lg:16 --r-pill:999` | **`0`**（仅 `--r-dot:2px` 给状态点） | 像素图零圆角；圆角是最刺眼的"现代 Web"信号 |
| 描边 | `1px solid rgba(255,255,255,.08)`（几乎看不见） | **`1px solid #B1A077` + `inset 0 0 0 1px #D9CDAF`** | 复刻 9-slice 的 2px 双层 |
| 阴影 | `0 8px 32px rgba(0,0,0,.45)`（模糊） | **`3px 3px 0 #14121C`**（硬偏移，0 模糊） | 像素画的投影是硬色的 |
| 模糊 | `backdrop-filter: blur(16px) saturate(140%)` | **禁用。0 处。** | 本轮语言的第一判据 |
| 过渡 | `transition: all 220ms` | `120ms`，**只过渡 `background`/`border-color`** | 像素 UI 不该"滑"，只该"亮" |

**为什么硬偏移是 `3px 3px` 而不是 `2px 2px`**：`2px` 在 1440 宽下太弱，面板浮不起来；`3px` 对应 16px 素材的 1/5 格，观感是"纸被钉在桌上"，且不与 1px 描边抢戏。**这是唯一一处自由数值**，其余全部来自采样。

### 3.2 分层：纸在墨上

```
┌─ 页面底 #1C1A26（ground，游戏地面色）─────────────────┐
│                                                        │
│   ╔═══════════════════════╗  ← 纸卡 #D3BF8F + 双层描边  │
│   ║  内容区 #ECE3CE  ←── 再亮一层的"纸"                 │
│   ╚═══════════════════════╝     + 3px 3px 0 硬阴影      │
│                                                        │
└────────────────────────────────────────────────────────┘
```

面板**不再"浮在场景上"**（浮 = 模糊 + 半透），而是**"贴在场景上的一张纸"**（不透明 + 硬边 + 硬投影）。场景因此不会被面板"蒙白"，视觉上两者是**并置**而非**叠加**。

### 3.3 ⚠️ 量化发现：状态色不能做文字（这条改变了整个规范）

我实测了对比度（WCAG 2.1）：

| 状态色 | on tan `#D3BF8F` | on 纸 `#ECE3CE` | on 墨 `#14121C` |
|---|---|---|---|
| done `#22C55E` | **1.26** ✗ | 1.78 ✗ | 8.13 ✓ |
| ready `#F59E0B` | **1.19** ✗ | 1.68 ✗ | 8.63 ✓ |
| in_progress `#3B82F6` | **2.03** ✗ | 2.88 ✗ | 5.04 ✓ |
| failed `#EF4444` | **2.08** ✗ | 2.95 ✗ | 4.93 ✓ |
| dead `#C77DFF` | **1.49** ✗ | 2.11 ✗ | 6.89 ✓ |

**全部远低于 4.5:1，甚至低于 3:1 的大字门槛。** 结论：

> **状态色一律不做文字色，只做「实心色块 + 墨色文字」。**

验证反向（`#14121C` 墨字压在色块上）：

| 色块 | 墨字对比度 | 判定 |
|---|---|---|
| done `#22C55E` | 8.13 | ✓ |
| ready `#F59E0B` | 8.63 | ✓ |
| in_progress `#3B82F6` | 5.04 | ✓ |
| failed `#EF4444` | 4.93 | ✓ |
| dead `#C77DFF` | 6.89 | ✓ |
| blocked `#6B7280` | **3.83** | ✗ → 改**白字**（4.83 ✓） |
| pending `#4B5563` | **2.45** | ✗ → 改**白字**（7.56 ✓） |

**这条不是设计偏好，是物理约束。** 米色纸面上，任何饱和的状态色都会糊掉——这正是现状用"彩色小圆点 + 深色文字"而不是"彩色文字"的原因，但现状是在**深灰蓝玻璃**上做，那里亮色可读。换到米色纸后，**同样的色必须反向使用**。

文字色实测：

| 文字 | on tan | on 纸 `#ECE3CE` |
|---|---|---|
| 墨 `#14121C` | **10.25** ✓ | **14.51** ✓ |
| 暗棕 `#6D543A`（`brown` 内描边） | **3.90** ⚠️ 仅大字 | **5.52** ✓ |
| `#886644` | 2.88 ✗ | 4.08 ✗ |

⇒ **正文用墨 `#14121C`；次级文字用 `#6D543A`，且必须放在纸 `#ECE3CE` 上（5.52），不许直接放 tan 上（3.90）**。这条直接决定了卡片的分区结构：**tan 是外框，`#ECE3CE` 才是写字的地方**。

### 5.2 三块各自的分区规则

**header（48px，纸卡）**

| 区 | 内容 | 规则 |
|---|---|---|
| 左：品牌 | 星座标 + 可编辑名 | 标 24×24，**去掉圆角**，木色底 `--paper-wood` + 双层描边 |
| 中：**代码看板摘要搬走后留空** | — | 看板已在侧边栏；header 中部**留白**，这是"少即是多"的地方 |
| 右：命令组 | 暂停/继续/视图/设置 | 每个按钮独立小卡：`--paper-0` 底 + `2px 2px 0` 硬阴影，**按下变 `--shadow-press`** |

**sidebar（320px，纸卡）**

> ⚠️ **沿用 R99，不做页签**。用户原话：「不是分成两个 tab，这两个 tab 应该可以同时看到才对」。
> 所以侧边栏是**两块常驻、上下堆叠、整体滚动**（`.sidebar-body` 统一滚）。本轮**只换外观，不动这个结构**。

| 区 | 内容 | 规则 |
|---|---|---|
| 头部 | 折叠开关 | 单个小方块按钮，`--paper-0` 底 + 1px 墨描边 + `2px 2px 0` |
| 区块标题 | `AGENTS` / `任务图` | **全大写 + `--tracking-label` + `--ink-1`**。R99 之后它是"这块是什么"的唯一标识，所以要给足字距、不许缩小到看不见 |
| Agent 区块 | Agent 卡堆叠 | 每卡：`--paper-0` 底 + 1px 墨描边 + `2px 2px 0` 阴影，**卡之间 8px** |
| Agent 卡内部 | 部门色条 + 名字 + 状态块 + 单数 | **左侧 3px 实心部门色竖条**（`--accent-*`）——这是部门色唯一的用武之地 |
| 卡内状态 | 实心色块 + 墨/白字 | 见 §3.3。**绝不做彩色文字** |
| 任务图区块 | 依赖图（复用 `board.js`） | 图区**不设底色**（透明，直接露出 `--paper-1` 面板），只有连线与节点有颜色。图区高度按内容取，不 `flex:1` |

**footer（36px，纸卡）**

| 区 | 内容 | 规则 |
|---|---|---|
| 状态带 | 组 → 读数 | 组间 **1px 墨竖线**（`border-left: 1px solid var(--ink-2)`），不用面板分隔 |
| 读数 | 数字等宽 | 数字用 `--mono-font`，**`font-variant-numeric: tabular-nums`**（跳动时不抖） |
| 分组标签 | `TICK` / `SEQ` / `SP` | **全大写 + `--tracking-label` + `--ink-1`** |

### 5.3 间距与分组规则（"现代化"靠这个，不靠毛玻璃）

1. **间距只用 `--s-*` 四档**（4/8/12/16）。现状 `--s-5/6`（24/32）在这三个 48px/36px 的条里一次都用不上——**条状 HUD 不放大间距**。
2. **卡与卡之间恒定 8px**，卡内边距恒定 8px（不用 12，条太矮）。
3. **分组靠线，不靠留白**：footer 的组间用 1px 竖线；sidebar 的区之间用 1px 横线 + 4px 空隙。
4. **同层级内不许出现第二种描边**。整个 HUD 只有两种描边语言：纸面（`--paper-2`+`--paper-3`）和墨面（`--ink-0`）。**不许出现"半透明白线"**。

## 六、字体方案

### 6.1 结论：**不引入外部字体**，用系统等宽栈

```css
--ui-font: ui-monospace, "SF Mono", Menlo, Consolas, "PingFang SC", monospace;
```

**理由**：

| 方案 | 优点 | 缺点 | 裁決 |
|---|---|---|---|
| 引入像素字体（如 Silkscreen / Pixelify Sans，OFL） | 最贴主题 | 中文字形几乎无覆盖；需自托管 + 进 `CREDITS.md`；CJK 回退时中英混排会**断裂**（像素英 + 黑体中） | ✗ |
| **系统等宽栈** | 零许可风险、零加载、CJK 全覆盖；等宽天然带"终端/控制台"的机械感 | 不是像素字 | **✓** |

> **像素感靠三件事造，不靠字体文件**：① **小字号**（11–13px）+ ② **全大写标签 + 0.10em 字距** + ③ **等宽字形的固定步进**。
> 在 13px 中文正文上硬塞像素字体，中英混排会先崩——**得不偿失**。中文字形本身就是"块状"，等宽栈已经足够。

**许可**：系统字体，**无需任何许可声明**，`CREDITS.md` 不改。这满足任务书"不确定就用系统字体的像素感组合（更安全）"。

## 九、风险与待确认

| # | 风险 | 缓解 |
|---|---|---|
| R1 | **米色纸面 + 深色场景 = 对比极强**，可能有人觉得"刺眼" | 这是像素游戏的常规观感（星露谷/开罗都是深底 + 米黄面板）。若用户嫌亮，降级路径：把 `--paper-1` 换成 `--paper-wood #97714A`（木色面板），语言不变 |
| R2 | 状态色块在 11px 字上，`blocked`/`pending` 用白字，其余用墨字——**同一排里混用两种字色** | 有意为之：色块亮度不同，字色是被对比度逼出来的。已实测每格 ≥4.83 |
| R3 | `--ease: steps(1,end)` 让所有过渡"瞬切"，可能显得生硬 | 这正是像素 UI 的正确行为。若用户觉得太硬，退回 `--t-hover: 120ms`，`--ease` 用 `ease-out` |
| R4 | 侧边栏 320px（`sidebar.css` 的 `--sidebar-w`）+ 双层描边 + 阴影，实际内容宽 ~306px | **沿用现状 320px，不改宽度**（`--board-members-w` 已是 0，成员卡整宽） |
| R5 | **本轮只出文档与 mockup**，`tokens.css` 未改，代码与规范暂时不一致 | 实现任务必须先改 token 再改组件，否则会写出"新组件引用旧 token"的半成品 |
