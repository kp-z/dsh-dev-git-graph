# CHANGELOG

本文件记录 dsh-daily 的每个可交付版本。开发期的**逐轮记录**在 [STATUS.md](STATUS.md)（每轮必带真实命令与输出）。

## 0.6.3 — 简报资讯合并调研结果（把两条链路接起来）

- `findingsToNews()`：调研结果 → 简报资讯，**每条写明来源与命中的检索词**（可追溯）
- `mergeNews()`：**调研优先** + 按 URL 归一化去重（日报与调研很可能撞同一条）
- `BriefNews.source: 'daily' | 'research'`：用户能看出哪条是主动搜来的
- `buildBrief()` 只读**已缓存**的调研结果 —— 简报不偷偷触发网络请求
- **实测召回 1 → 10 条**（全部来自主动搜索）；同时暴露下一层问题：
  多条靠语义上很泛的 `dashboard` 命中，带回了无关内容 ——
  **简报的资讯质量此刻等于调研检索词的质量**，下轮要动的是检索词侧

## 0.6.2 — 简报相关性：强弱两级

- `projectTermList()` + `TermStrength`：**依赖名与作用域词一律强**（项目独有），
  领域词按长度分强弱（ASCII ≥7 / 中文 ≥4 为强）
- `selectRelatedItems()` 新判据：**强词命中即相关；只有弱词时要 ≥2 个**；得分 = 强×3 + 弱
- **真实数据复测召回没有回来（仍是 1 条）**，但原因不是规则：
  命中的 `react` 来自依赖名（按设计就是强词）。真相是**通用新闻里几乎没有与本项目依赖相关的内容**
  —— 说明简报的召回问题**不是"过滤太狠"能解决的**，正确解法是
  **用项目关键词主动去搜（HN/GitHub）再与日报合并**，这正是用户指出的方向、也是下轮第一件事

## 0.6.1 — 简报相关性：过滤过泛词

- 新增 `isMatchableTerm()`：匹配场景的停用词（中文 `数据/管理/状态/系统/…`，英文 `web/data/test/api/…`），
  英文 ≥4 字符、纯中文 ≥3 字，并复用研究侧的 `isDomainKeyword` 挡结构词
- **真实数据前后对比**：`news` 由 10 条（主要靠 `test`/`web`/`数据` 命中，含完全无关条目）
  变为 1 条（命中 `react`，内容确实与 React 生态相关）；命中过泛词的条目 **0**
- **同时暴露另一半问题**：精度上去、**召回掉下来**（10 → 1）。
  下轮改为**强弱两级**：强词命中即相关，弱词加权但不单独构成相关

## 0.6.0 — 第三阶段第②期：项目简报接口

用户新方向：每次取新闻时像调研一样针对当前项目给出 AI 建议（概念理解 / 最新资讯 / 进化建议）。

  `isDomainKeyword` 过滤

## 0.5.3 — 单源总预算（一个慢源不该独占整轮刷新）

- 效率报告实测：YouTube 的抓取耗时在 **2.7 s ↔ 46.8 s** 之间剧烈波动，单源就能把整轮刷新拖到 1 分钟以上
- 根因澄清：`fetchText` 的 12s 是**每次尝试**的超时，默认还重试 2 次 → 最坏 ≈ 40s。
  缺的不是"超时"，而是**"一个源最多花多久"的约束**
- 新增 `SOURCE_BUDGET_MS = 20_000`（源这一层；`CollectOptions`/`CollectEnv` 均可覆盖）；
  到点中止并按失败记录，错误信息写明 **`单源超时：超过 20s 预算已中止`**（不是底层 `aborted`）
- 该源随后进入既有的退避/轮转逻辑（下一个周期才会再被选中）

## 0.5.2 — 巡检工具 + 它抓到的两个真问题

- **新增 `scripts/patrol.mjs`（`npm run patrol`）**：一次跑出**两份报告** ——
  ① 功能检查（逐项带证据）② 运行效率 / API 请求效率（分阶段墙钟、**外部请求数**、接口延迟与体积），
  落盘 `reports/patrol-<时间>.md` 与 `reports/latest.md`
- **修：磁盘来源被"宿主是否存在"卡住**（巡检发现的真 bug）
  `hostCandidates()` 在"没有任何宿主作用域"时**提前返回**，而磁盘来源（`storages/workspace.json`）
  的收集写在那之后 → dev-server 这类没有 cordis 宿主的环境里**那条路永远跑不到**；
  真实宿主有 host，所以掩盖了这个设计错误。磁盘来源本来就不需要宿主 —— 已提到提前返回之前，
  并断言"诊断里 `hosts: 0` 时也照样能用磁盘来源"
- **dev-server 现在也跑一次 `autoDetect()`**：真实入口（`bootstrap`）会做这件事，
  dev-server 之前不做 → `/api/state` 里永远没有 `project.detect`，
  联调环境与真实宿主**行为不一致**（巡检因此报"诊断字段缺失"）。现在两边一致
- **巡检脚本自己也犯过错并已修**：探了不存在的 `/api/prefs`（偏好数据在 `/api/state` 里）、
  报告文件名用了 UTC 时间（本地 11:08 会写成 `0308`，看着像坏了）

## 0.5.0 — 按通道改写提问：风险与坑改走 issues/PR

- **新增第三个通道 `github-issues`**（issues/PR 搜索）。实测依据：
  `antv g2 breaking changes` 在**仓库搜索**上 `total=0`，在 **issues 搜索**（`repo:antvis/G2 breaking changes`）上 **total=20**
  —— "破坏性变更/坑"这类信息**长在 issue 与 PR 里**，不长在仓库简介里；通道选错，改词也白费
- **维度 → 通道**（`providersForDimension`）：`risks` → issues + HN；`peers` → 仓库 + HN；其它 → 仓库 + HN
- `peers`/`risks` 的检索词改成通道认的写法：`<领域词> in:name,description stars:>50`、`<依赖> breaking change`
- **修掉"章法被全局上限架空"的根因**：全局 `maxQueries` 默认 6，而选取是维度优先 →
  keyword(3)+dep(3) 吃满，`tech`/`peers`/`risks`/`ai` 一条都没轮到（实测 16 次请求全是 keyword+dep，
  **新加的 issues 通道压根没用上**）。改成**按维度轮流取（round-robin）**、上限 8 ——
  上限再紧，每个维度都至少有一份
- 新通道**漏登记在 `acceptsQuery`** → 会接受中文检索词（又是"打过去 200 但 0 条"的静默浪费）。
  已修，并加回归守卫：遍历所有通道断言"英文接受、中文拒绝"，**以后加通道忘了登记测试会红**

## 0.3.9 — AI 中文介绍接通

- `generateIntros()`：任何失败都返回 `null`（超时 / 抛错 / 推理烧光预算没正文 / 输出解析不出来）
  → 退回确定性兜底：**模型抽风最多让介绍没那么好，不会让卡片空着，也不会让整轮检索失败**
- `maxTokens` 按条数给足（每条 ≈220 token × 条数 × 2，下限 512）—— 推理 token 与正文共享上限
- 联调抓到一个**静默不生效**的真问题：真实流事件类型是 **`text-delta`**，我第一版写成 `text`
  → 永远收不到正文 → 静默退回兜底（看起来"AI 没生效"却没有任何报错）

首个版本：H1–H5 全部落地，宿主侧已在运行中的 dsh 实例验证通过。

### Added

**采集层（11 个源，单源失败隔离）**
- Hacker News（经 hnrss，带分数与**讨论页链接**）、arXiv（cs.AI/CL/LG/CV）、
  GitHub Search API（近 30 天新建、star 最高）、YouTube（RSSHub 镜像池）、
  哔哩哔哩·热门 / 哔哩哔哩·排行榜、少数派 / IT之家 / Solidot / 阮一峰、以及任意自定义 RSS
- 零运行时依赖的 RSS 2.0 / Atom 1.0 / RSS 1.0(RDF) 解析器（28 组断言、6 个真实样本）
- RSSHub **镜像池**：健康度跨轮持久化、成功镜像优先、失败原因逐条聚合；
  采集前**并行预热**按延迟排序（YouTube 单源 39.8s → 7.7s）

**排序与调教**
- 去重两段式：URL 规范化精确合并 → 标题相似度合并（词级 `max(Jaccard, containment)`，阈值 0.8）
- **OPML 导入 / 导出**：把已有阅读器的订阅一次性带过来；按规范化 URL 去重，
  **内置源也参与判重**（避免同一份内容被抓两次）；已有条目不覆盖用户改过的名字；
  导入写进 `prefs.extraFeeds`，**下一次刷新即生效**，不需要改配置或重载 profile。
  导出把内置源 + 自定义源一起给出，可带回其它阅读器（`daily_opml` 工具 + `/dsh-daily/api/opml`）
- **跨天去重**（`dedupeWindowDays`，默认 3 个日历天）：窗口内推过的条目重罚到 ×0.2 并标注「X 月 X 日已推过」；
  重罚**不删除** —— 真正重要的事仍然进得来，只是排在后面；`daily_search` 依旧搜得到
- 评分：新鲜度半衰期 × 源权重 × 主题命中 × 关键词 × 平台热度信号（HN 分 / star / 播放量），
  **每条都带可解释的推荐理由**
- 自然语言调教：主题 / 关键词 / 屏蔽词 / 来源权重 / 每日配额，落盘后**立即重排当天**
- 反馈学习：👍 / 👎 / 已读 / 隐藏，跨天累积

**日报与主动推荐**
- 按主题分组的 Markdown 日报 → `~/.dsh/daily/digest/YYYY-MM-DD.md`
- **归档与周报**：侧边栏日期导航（按天翻阅，「回到今天」只在历史态出现）；
  周报汇总最近 N 天（最值得看 / 主题分布 / 每天条数与断采预警 / 源健康）→
  `digest/week-<起>_<止>.md`（`daily_weekly` 工具 + `GET /dsh-daily/api/weekly`）
- **可选 AI 摘要**（`aiSummaryEnabled`，默认关）：给当天前 N 条生成一句中文摘要，
  侧边栏与日报都显示（带 ✨ 标记区分于原文摘要）；侧边栏有按钮可随时给**已抓到**的条目补摘要；
  按条目缓存 30 天 / 500 条；单条失败隔离，失败原因（含 max-tokens）显式报告
- 紧凑摘要注入 `systemPrompt`（默认 6 条、实测 405 tokens），让模型**自己**提起今天值得看的
- `pickDiverse` 保证「推荐**不同**类型」：主题轮转 + 每源上限 2（修复前 6/6 全是 HN 技术新闻）
- 每日 `08:00` 定时 + 启动补抓；`computeNextRun` 用自串链 setTimeout，天然纠正漂移

**展示与接口**
- 右侧栏「日报」tab（`betterSidebar.registerTab` + iframe），常驻网页
- 网页：分类筛选 / 搜索 / 仅未读 / 视频卡（封面·时长·播放量）/ 👍👎✓隐藏 / 调教输入 /
  刷新浮层（绝对定位不推版）/ 日报 Markdown 弹层 / 空态 / 错误态 / 明暗主题 / 280–420px 自适应
- **页脚两个入口**：「订阅管理」（选 OPML 文件导入、看/移除自定义源、复制或下载 OPML）与
  「本周回顾」（弹层里看周报）—— 不用再对模型说或敲 curl
- 条目 meta 里的「讨论」入口（HN 这类源的价值一半在评论区）

**长期运行**
- **归档分级保留**：`days/*.json` 一天约 50KB，一年 ~18MB。超过 `archiveCompactAfterDays`
  （默认 60 天）自动**压缩成索引**（丢摘要/热度/理由，保留标题/链接/主题/分数/已读态），
  实测 49.6KB/天 → 26.8KB/天（**−46%**，全年外推 17.7MB → 9.6MB）；
  `archiveDeleteAfterDays`（默认 **0 = 永不删除**）才真删
- 整理**每天最多自动跑一次**，挂在采集完成之后（用户不需要知道它存在，但长期跑必须有人做）
- `daily_prune` 工具 / `GET|POST /dsh-daily/api/storage`：容量统计 + 预览 + 执行；
  **默认只预览不写盘**（破坏性操作必须先能看见会发生什么）
- 首次使用：空态里的「开始抓取」按钮（不必去找右上角的图标）

**加载期安全（宿主半体加固）**
- `apply` 整体包 try/catch + 装配拆到 `applyInner`：**加载期失败只降级，不炸宿主**
  （客户端半体已经因此把用户界面打成错误页一次，宿主半体不该还有同类缺口）
- `bootstrap` 同样整体兜底（拆到 `bootstrapInner`）：否则一段接线抛异常只会变成
  一行 unhandled rejection —— 日志里看不出"少接了什么"
- `installPromptSection` 与 `installSchedule` 各自兜底：**一段失败不该让后面几段跟着不接**
  （这两段早先是裸的，一抛会静默跳过 AI 接线与启动补抓）
- 新增 `test/host-safety.test.js`（4 组契约测试，静态检查 `src/index.ts`），
  并**反向验证**过：同一套检查跑在加固前的 0.2.3 产物上，契约 1、3 均报错
- 顺带查明：宿主 `inject = ['tools','webServer']` 的 fail-loud 设计**是安全的** ——
  inject 不满足时条目是 `pending` 而不是 `failed`，而 `pending` 不会拖垮 boot

**AI 中文介绍接通（把"卡片写清楚"的另一半补上）**
- `generateIntros()`：把结果交给模型写一句中文介绍，**任何失败都返回 `null`**
  （超时 / 模型报错 / 推理烧光预算没写出正文 / 输出解析不出来）→ 调用方退回确定性兜底，
  于是"模型抽风"最多让介绍没那么好，**不会让卡片空着，也不会让整轮检索失败**
- 接进 `runFindings`：有模型路由（显式配置或宿主默认）就让 AI 写；不然全走兜底
- `maxTokens` **按条数给足**（每条约 220 token × 条数 × 2 倍余量，下限 512）——
  推理 token 与正文共享上限，这是 dsh-rss 踩过的坑（正文还没开始写就把预算烧完）
- **联调抓到一个静默不生效的真问题**：真实流事件类型是 **`text-delta`**，
  我第一版写成 `text` → 永远收不到正文 → **静默退回兜底**（看起来"AI 没生效"但没有任何报错）。
  现在两种都认，并让假模型也认介绍类请求

**结果卡片：头图 + 中文介绍（用户：「结果卡片需要写清楚，最好配上头图和中文介绍」）**
- 新增展示层 `src/present.ts`（纯函数，可测）：
  - **头图** `thumbForFinding`：GitHub 仓库 → **owner 头像**（稳定、无第三方、无 token）；
    其它来源 → **站点自己的 favicon**。刻意不用 Google/DDG 的 favicon 服务 ——
    多一个第三方就多一个不可达的失败点（YouTube 封面的教训）。取不到就返回 `undefined`，
    交给界面走**已钉住的占位块契约**，绝不给一个会变成破图的地址
  - **中文介绍**：AI 写（`buildIntroPrompt` 要求严格 JSON 数组、一句中文、不许编造）；
    拿不到 AI 或输出坏掉时走**确定性兜底**（用 ★star / 分数 / 讨论数等结构化事实拼一句中文），
    并且用 `introSource: 'ai' | 'fallback'` **如实标明**，不冒充模型写的
  - **来源中文名** `sourceLabel` + 命中检索词一并展示（保留可解释性）

**调研章法：检索从"一堆词"变成"分维度的调研大纲"**
- 用户意见：「链接到项目后需要根据项目搜索，**要有章法**」
- 新增**维度模型**（`RESEARCH_DIMENSIONS`）：每个维度 = 一类问题 + **自己的预算**
  | 维度 | 问的问题 | 预算 |
  |---|---|---|
  | 领域关键词 | 这个项目的领域里最近有什么新东西？ | 3 |
  | 依赖动态 | 我用到的依赖最近有什么变化、升级要注意什么？ | 3 |
  | 技术栈实践 | 我这套技术栈最近有什么值得采纳的做法？ | 2 |
  | **同类项目** | 别人在做类似的东西时是怎么做的？ | 2 |
  | **风险与坑** | 有什么已知的破坏性变更、安全公告、弃用？ | 2 |
  | AI 补充 | （模型看了画像后补充的角度） | 3 |
- **预算在生成与检索两侧都生效** → 任何维度都抢不走别人的份。早先是"扁平列表 + 按顺序截断"，
  谁排前面谁被搜 —— 实测结果就是"依赖"类词吃光预算，"风险/坑""同类项目"一条都轮不到
- **计划规模 = 各维度预算之和**（不再是拍出来的 8）
- **结果按维度归位**：`groupFindings()` + 接口返回 `groups` + 工具输出分节
  （用户看到的是一份有条理的调研，而不是一堆链接）

**根因定位并修复：没有活动会话时识别不到项目（诊断功能首次发挥作用）**
- 从 0.3.5 的**诊断**直接读出根因：
  `hosts: 2` · `sessions: ok=true, **count=0**` · `workspaceRegistry: ok=false` · `candidates: 0`
  —— `ctx.sessions` 是**内存**会话存储（服务描述原文 *In-memory session store*），
  headless 服务上没人对话时它就是**空的**；`workspaceRegistry` 在那台不可用。
  **两个服务来源都拿不到东西 → 候选恒为空 → 静默停在默认项目**。
  这次不是"取不出 cwd"，而是**来源本身是空的**
- **新增磁盘来源**：DSH 的工作区注册表存盘 `<DSH_HOME>/storages/workspace.json`
  —— 里面是**精确路径**（不像会话目录名那样把路径 encode 成有损的连字符、
  也不像会话数据那样是 zstd 压缩），按目录 mtime 排序（最近动过的项目更可能是当前项目）
- **DSH 主目录改为从插件自己的数据根推导**（`dirname(dataDir)`，环境变量优先）：
  ① 用户自定义 dataDir 时能跟上真实的 DSH 主目录
  ② 单测里数据根是临时目录 → 天然读不到开发机的真实工作区（**密闭**）

**修复 + 可观测：真实宿主里识别不到项目（用户实测反馈驱动）**
- **主要嫌疑已修**：`extractProjectDir` 原先只走 `Object.entries()` 泛走遍历 ——
  它**只看得见自有可枚举属性**。而 DSH 的 `Session`/`Workspace` 是类实例，
  `cwd` 很可能在私有字段（`#header`）后由原型 getter 暴露 → 泛走什么都看不到，**且不报错**。
  现在增加**显式访问路径**（`cwd` / `header.cwd` / `meta.cwd` / `workspace.path` … 16 条，
  按路径直接取值可穿透 getter），泛走作为兜底；深度 3→4、节点 60→200
- **加了诊断（这是关键）**：识别失败是静默的，而那台机器我拿不到 shell（受限跳板）。
  现在把"试了哪些来源、各读到几个、候选数、候选样本（含探到的路径）、为什么没切"
  记进 `currentProject().detect` 并暴露在 `/api/state` —— **故障从此可远程定位**

**界面：项目状态改为只读（不再可选）**
- 侧边栏顶部原来的**下拉切换器 + `＋` 新增**全部移除，换成一行只读状态：
  `项目 <名字>` + `自动识别 / 手动指定 / **未识别到项目**`
- **未识别时明说**（配提示色与悬停说明），而不是继续显示默认项目的名字 ——
  后者看起来像"它正在按我的项目工作"，实际上是默认数据
- 悬停提示会直接给下一步：`未能自动识别项目，正在用默认数据 —— 在项目目录里开一个会话即可跟随`

**修复：项目自动识别在真实宿主里不生效**
- **根因**：宿主半体只声明了 `inject = ['tools','webServer']`，却用 `ctx.get('sessions')`
  读没声明的服务 —— cordis 里这**会抛**（`cannot get property "X" without inject`），
  被我的兜底 try/catch 吞掉 → **候选永远是空** → 自动识别静默失效。
  这与当初把客户端半体打成错误页的是**同一类问题**。
- **修法**：可选服务改在**各自的 `ctx.inject([name], cb)` 作用域**里声明式获取
  （`sessions` / `workspaceRegistry`），service 累积多个作用域、读取时依次尝试；
  拿到哪个用哪个，都没有就保持默认项目（不猜）
- **加固**：新增宿主契约测试「可选服务必须用各自 inject 作用域获取」+ 两条集成测试
  （模拟 cordis 抛异常、多个作用域依次回退）

**定向检索质量优化（发布后真实对比驱动）**
- **检索词具体化**：新增 `isSpecificQuery` —— 多词/中文/够长的单词才算具体。
  单独一个通用技术名不再成词（实测 `react` 单独搜回来的是「Honda conducts successful
  launch and landing of…」），技术栈名一律与限定词组合（`TypeScript best practices`）

- **结果侧按检索词具体度加权**：一条结果必然来自某条检索词，那"这条词有多具体"就是现成的
  相关性先验 —— `heatOf` 现在把它算进去，过泛词的结果自然沉下去
- **真实前后对比**（同一项目 mvizlite，真实网络）：

**定向检索（调研链第④环）**
- `POST /api/findings` / `daily_research({action:'run'})`：拿③生成的检索词**真去搜**，
  结果落盘 `<项目>/findings.json`；每条结果都记住**是哪条检索词找到的**（可解释）
- 两个通道：**HN Algolia** 与 **GitHub 搜索**（都是关键词驱动；YouTube/Google News 在多地不可达，不进关键路径）
- 失败隔离：N 条词 × 2 通道的每一格失败只记进 `errors`，**绝不抛**；单请求超时用 AbortController
- 三个实测出来的坑（都是"HTTP 200 但没有结果"这种安静失败）：
  1. **中文检索词打英文语料** → 12 次请求全 200 却 0 条。现在显式过滤（记录 `skipped`）+

  2. **包名带 `@scope/` 与自然语言后缀** → GitHub 直接 422、HN 0 条。

  3. **预算算错**：早先 `maxQueries` 是先切片再过滤，预算被注定跳过的中文词吃掉 →
     一个请求都不发。现在只把"通道认的词"计入预算

**数据完整性**
- **刷新改为「合并当天」而不是「覆盖当天」**：早先 `runRefresh` 用本轮采集结果整份覆盖，
  导致 ① 定向刷新（`sourceIds`）会冲掉当天其它源的内容 ② 同一天第二次刷新时若某个源失败，
  **那个源上午抓到的条目会从今天的列表里消失** —— 用户看到的就是"刷新一下，条目反而变少了"。
  现在按规范化 URL 去重后取并集再统一排序，并继承两个必须继承的字段：
  `firstSeenAt`（丢了老条目会被当成新内容，影响跨天去重与新鲜度）与
  `aiSummary`（丢了等于每次刷新都重新调用模型 —— 缓存只覆盖"跨天重复"，覆盖不了"同一天刷新两次"）。
  源状态同样合并：本轮跑过的用新状态，没跑的沿用上一次，否则一次只跑 YouTube 的刷新
  会让日报里其它 10 个源"消失"

**可靠性**
- **YouTube 频道轮转 + 失败退避**：本机 YouTube 依赖一个免费公共 RSSHub 镜像，5 个频道每轮全量
  请求它会触发 429（实测一次 2/5 频道失败、一次**整源 0 条**），且该源占了整轮刷新耗时的绝大部分。
  改为**按 LRU 轮转**（每轮 3/5 个频道，按"上次**尝试**时间"排序而不是上次成功时间 ——
  否则老失败的频道会永远被优先选中）+ 连续失败按 2 的幂退避。
  实测改善：改前两个探针一次 2/5 失败、一次整源 0 条；改后连续两轮 **0 失败**、两轮覆盖全部 5 个频道。
  轮转说明会进源状态（日报与侧边栏 tooltip 都可见），**条数变少是轮转不是故障**

- **视频封面被自己误杀**（H5 复验发现）：封面用 `loading="lazy"`，而"请求挂住就超时换占位块"的计时器
  在元素**创建时**就启动了 —— 屏幕外的卡片浏览器还没开始下载，计时器已到期，
  于是**可用的封面被永久换成占位块**。实测真实数据的 16 张视频封面里，
  bilibili 那 8 张（curl 200 / image-jpeg）全部被误杀。
  改为「占位块常驻底层 + 图片进入视口才插入并盖在上面」：不再需要计时器，
  没有"误杀"这回事，挂住的源（YouTube 缩略图域名本机不可达）也只是盖不上来而已
- **错误态文案判错了原因**：接口 503 时提示却让用户「把页面放在 /dsh-daily/ 下」——
  那是给"直接打开文件"用的建议，而页面当时**已经**在 /dsh-daily/ 下，
  等于让用户去做一件他已经做过的事。改为按是否由宿主路由提供来分流文案
- **演示数据没在统计行标注**：接口挂掉时页面会切到内置演示数据，
  但「10 条 · 8 未读 · 7/8 源正常」看着和真实数字一模一样（标题与页脚虽然也标了，但容易被略过）。
  改为统计行以醒目的「演示数据」徽标开头
- **敏感文件检查被绕过**（自测当场抓到）：`shouldSkipDir` 把"点开头的条目"一律当目录跳过，
  于是 `.env` / `.env.local` 走了目录分支 —— 内容确实没被读（无泄漏），但**审计记录里没有它们**，
  用户看不到"跳过了哪些敏感文件"。改为先用 `readdir(withFileTypes)` 分清文件/目录，再各套规则；
  敏感文件名同时从 `topLevel`（会进摘要）里排除
- **绝对路径没走 `resolve()`**：`normalizeDir` 早先对绝对路径直接用原值，
  于是 `/tmp/a/../a/b` 与 `/tmp/a/b` 被当成两个项目 —— 同一目录两个身份，数据会被劈成两份。
  被「同一目录的两种写法必须完全相等」这条测试当场抓到
- **点击卡片不跳转**（用户报的 bug，两个问题叠在一起、症状一模一样）：
  ① 代码注释一直写着"整卡覆盖式的 `<a>`"，但 CSS 里**没有 `position:absolute`** ——
  它是个高度接近 0 的静态块，真实用户点到的是它下面的标题 div（命中测试证实：
  `elementFromPoint(卡片中心)` = `DIV.dd-item-title`，无链接祖先）。
  ② 代码**从不检查 `window.open` 的返回值**，被环境拦下时返回 `null` 且无异常 —— 毫无痕迹。
  修法：`.dd-item{-relative}` + `.dd-item-link{absolute;inset:0;z-index:1}` +
  交互控件抬到 `z-index:2`；并加完整的打开降级链
  （`window.open` → 父级 postMessage → 自动复制链接 + 明确提示，**绝不留死点击**）。
  另加 2 组契约测试把"覆盖层定位"与"消息协议两侧一致"钉死 ——
  **这两条测试如果早就在，这个 bug 根本进不来**
- 修掉 README 里两处**与实现不符**的说明：回归清单还写着 69 组单测与手工 diff 循环；
  「已知限制」还写着封面"走 6 秒超时降级"，而 R12 已经把计时器整个删掉了
- **轮转记录在源失败时被丢掉**：源全部失败要抛错（好让状态显示 ❌），但抛错会把"本轮尝试记录"
  一起扔掉 → 失败计数永远停在 0、退避永不生效、挂掉的频道每轮都被重新选中。
  改为让失败带着记录走（`SourceFailure.rotationUpdates`）
- **成功分支漏传轮转记录**：只给失败分支加了 `rotationUpdates`，成功路径照原样返回 →
  **成功时轮转状态根本不更新**，LRU 会永远选中同一批频道。被集成测试直接抓到
- 修掉探针输出里会**被误读成用户偏好**的文案（它用的是合成偏好 `topics: ['AI']` 来演示主题加权，
  却在输出里写成"偏好主题 AI"，看起来像读了用户的真实配置；实际探针既不读也不写用户数据）
- **页面的字段白名单漏了 `aiSummary`**：后端正确返回了 AI 摘要，但 `normalizeItem` 没映射它，
  数据在这一层被静默丢掉 —— 表现是"功能跑通了、界面上什么都没有"。
  已在 `normalizeItem` 处留下注释：**新增条目字段必须同步这里**

## 0.5.4 — 摘要 token 预算 + 单源预算的真实数据证据

- **AI 摘要默认 maxTokens 1024 → 3072**（且加了 `min(256)` 下限）。
  依据是巡检日志里的实测：`失败 1 · 模型没写出正文就用完了 maxTokens=1024（终止原因 max-tokens）`
  —— 一次调用只写一条摘要、正文几十个字，但**带推理的模型会先把预算烧在思考上**，
  1024 对它是明显不够的，而失败的代价是那条摘要永久缺失
- **单源预算的"被中止"路径拿到真实数据证据**：巡检的定点复测新增"1 ms 预算"一段，
  实测输出 `⛔ 被中止 · 单源超时：超过 1ms 预算已中止`
  （R50/R51 只能靠单测证明，这条路径此前从未在真实数据上被观察到）
- 错误文案按量级选单位：小于 1s 显示 `1ms` 而不是四舍五入成 `0s`
