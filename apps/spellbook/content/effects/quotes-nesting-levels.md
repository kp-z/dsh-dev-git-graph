## 描述

一层引文用双引号，里面再引一层自动换成单引号，再里面又回到双引号——不用在 HTML 里写任何引号字符。

机制是 ==`quotes` 定义一串引号对，浏览器按 `<q>` 的嵌套深度取第 n 对==。`quotes: '"' '"' "'" "'"` 依次给出第一层的开合、第二层的开合，超出定义层数时回到第一对循环。嵌套深度由 `<q>` 的**层级**决定，不需要你标注「我现在是第二层」——那个信息本来就在 DOM 结构里。

所以引号字符不该出现在内容里。写在内容里的引号是「一段文本碰巧以引号开头」，而 `<q>` 的引号是「这段文本是一次引用」——后者能被样式统一改变（比如换一套中文引号「」），前者只能一段段手工替换。

## 代码

```html
<p class="zh">他说：<q>她当时说<q>这事<q>没那么简单</q></q>，然后就走了</q>。</p>
```

```css
.zh {
  max-width: 30em;
  font: 400 17px/1.9 "Songti SC", "Noto Serif CJK SC", serif;
  color: #26201b;
  /* @mechanism 按嵌套深度循环取用引号对；层数不够时回到第一对 */
  quotes: '\201C' '\201D' '\2018' '\2019';
}

/* @mechanism 用 lang 切换整套引号，比逐处替换引号字符可靠 */
.zh:lang(en) { quotes: '\201C' '\201D' '\2018' '\2019'; }
.zh:lang(ja) { quotes: '\300C' '\300D' '\300E' '\300F'; }

.zh q { color: #7a3b2e; }
```

## 边界

- 手写的引号字符不受 `quotes` 影响。最典型的失败是：内容里已经写了 `"`，同时用了 `<q>`，于是页面上出现**两层引号**——而这看起来像字体渲染问题，不像结构问题。
- `quotes` 里的引号要用转义序列（`\201C`）或成对书写的字符串。写成 `quotes: "" ''` 会得到一个空字符串，页面上什么也没有且不报错——引号看起来「没生效」，其实是定义成了空。
- 生成的内容（`q::before` 插进去的引号）属于**呈现**，读屏器通常读出来，但复制粘贴时可能带上也可能不带。若引号本身承载语义（比如引用条款编号），要写在内容里而不是样式里。
- 引号不参与断行避头尾的控制。引号落在行尾时可能被单独留在一行上，`line-break: strict` 管的是标点，不专门管生成的引号。
- 中英混排时同一段里两种引号体系会打架。真正稳妥的做法是让 `lang` 跟着文本走，而不是给整段定一套——`<span lang="en">` 才是那一段的引号依据。
