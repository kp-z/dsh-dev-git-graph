## 描述

一条从深到浅的同色系色阶，相邻两档之间「看起来」的明暗差距一样——不像在 sRGB 里那样，深的那几档挤在一起、浅的几档散得很开。

机制是 ==oklch 里的 L 是感知亮度，等步长改 L 就得到等感知的梯度==。sRGB 的 `#333` 到 `#444` 与 `#bbb` 到 `#ccc` 差的是同样的数值，但人眼看着前者几乎没变、后者变化明显——因为 sRGB 的数值与感知亮度之间是一条弯曲的映射。oklch 把这条曲线拉直了，`L` 从 0.3 走到 0.9 分五档，每档的观感差就是均匀的。

所以做色阶时真正该固定的另外两个量是 `C`（彩度）与 `H`（色相）：改 `L` 而不动它们，整条色阶会保持在同一个色相上。用 `hsl()` 的 `lightness` 做不到这一点——它到两端的彩度会塌，浅色端发灰、深色端发浊。

## 代码

```html
<div class="ramp">
  <i style="--l: 0.30"></i><i style="--l: 0.42"></i><i style="--l: 0.54"></i>
  <i style="--l: 0.66"></i><i style="--l: 0.78"></i><i style="--l: 0.90"></i>
</div>
```

```css
.ramp {
  display: flex;
  gap: 6px;
  padding: 16px;
  background: #14101a;
}

.ramp i {
  width: 46px;
  height: 46px;
  border-radius: 6px;
  /* @mechanism 只改 L，C 与 H 恒定，整条色阶才留在同一个色相上 */
  background: oklch(var(--l) 0.12 250);
}
```

```js
// @mechanism 亮度按等步长排，感知上的差距才会均匀
const step = (0.9 - 0.3) / 5
document.querySelectorAll('.ramp i').forEach((el, i) => {
  el.style.setProperty('--l', (0.3 + step * i).toFixed(2))
})
```

## 边界

- 浅色端的 `C` 撑不住：`L` 超过 0.9 之后，`oklch(0.95 0.12 250)` 这个颜色已落在 sRGB 之外，浏览器会做色域映射把它压回来，压多少各家算法不同。要保住浅色端的色相，得随 `L` 上升一起把 `C` 调小，而不是死守一个 `C`。
- oklch 的 `L` **不是** WCAG 的「相对亮度」，也不能直接拿来算对比度。`L: 0.5` 的色与 `L: 0.9` 的色之间未必达标 4.5:1——对比度要用 WCAG 的线性亮度公式算，那是另一个量。
- 色相角 `H` 是环形量，`0` 与 `360` 是同一个色相。做「色相偏移」的动效时从 350 往 370 走会看起来正常，从 350 往 10 走会因为数值往回跳而反向旋转。
- `oklch()` 里的 `L` 允许超过 1（表示更亮，靠色域映射压回去），负值也允许。写 `-0.1` 不会报错，会得到一个出乎意料的颜色，而不是黑色。
- 色阶本身没有解决「文字在哪些档上读得清」。每一档要配什么前景色，仍要逐个测对比度。
