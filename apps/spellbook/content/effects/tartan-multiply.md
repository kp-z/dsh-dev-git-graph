## 描述

一块格纹：深红宽带、藏青窄带，横竖各铺一遍，交叉处出现一组别的地方都没有的颜色。

机制是 ==同一组条纹横一遍、竖一遍，再让两层用 multiply 相乘==。竖直方向的红遇见水平方向的红，相乘得到更深的红；红遇见蓝，相乘得到偏紫的暗色；两条带子之间的空白处两层都透明，露出浅底。这些中间色不是选出来的，是乘出来的——这正是格纹读作「织物」而不是「格子」的原因：真实格呢的颜色就是经线纬线各染一次、叠在一起的结果。

乘法的方向决定了底色必须是亮的。`multiply` 的结果永远不会比两层都亮，所以底布要当成「没染色的浅纱」来选：底色一亮，每一种带子都只是把它按自己的色相压暗一档，交叉处再压一档。反过来做深色底格纹，该用的是 `screen`（永远不比两层都暗），逻辑完全对称。

## 代码

```html
<!-- @mechanism 横竖两组条纹来自同一段色标，只是方向不同 -->
<div class="plaid"></div>
```

```css
.plaid {
  width: min(320px, 78vw);
  height: 168px;
  /* @mechanism 底色是浅的「未染纱」：multiply 只会变暗，暗底会把两组带子一起压成黑 */
  background-color: #efe6d5;
  /* @mechanism 同一个色标序列（宽带 7px、窄带 3px、周期 34px）铺两遍，一横一竖 */
  background-image:
    repeating-linear-gradient(
      90deg,
      rgb(180 60 40 / 0.9) 0 7px,
      rgb(180 60 40 / 0) 7px 22px,
      rgb(46 62 110 / 0.85) 22px 25px,
      rgb(46 62 110 / 0) 25px 34px
    ),
    repeating-linear-gradient(
      0deg,
      rgb(180 60 40 / 0.9) 0 7px,
      rgb(180 60 40 / 0) 7px 22px,
      rgb(46 62 110 / 0.85) 22px 25px,
      rgb(46 62 110 / 0) 25px 34px
    );
  /* @mechanism 交叉区两条带子相乘，得到只有格纹才有的第三档颜色 */
  background-blend-mode: multiply;
}
```

## 边界

- 底色太深时两层一起被压黑，格纹只剩个轮廓。乘法只能变暗，这是它的物理性质，不是参数问题——要暗色底格纹请换 `screen` 并把带子调亮。
- 交叉色不只是「更深」：乘法是逐通道的，红色 × 藏青在蓝通道上压得更狠，色相会偏移，出现偏紫或偏褐的中间色。想要「只是变深」的干净格纹，就把两条带子写成同一色相的两个明度。
- 两组条纹的周期必须相同，否则交点连不成一条线，看起来是乱纹。周期相同、两条带子宽度不等，才读作 tartan；两条等宽同色就是 gingham（方格布）。
- `background-blend-mode` 只在**同一个元素的各个背景层之间**起作用，不会跟元素底下的内容混。要和后面的内容混，那是 `mix-blend-mode`。
- 带子用半透明色（这里 0.85–0.9）时，乘法结果会朝底色靠一点，交叉处的对比变弱。要最浓的交叉，两条带子都用不透明色。
- 它全部由背景层承担，所以任何 `background-size`、`background-position` 的改动都会同时移动两组带子，只有改色标才能单独调某一组。

## 备注

- 把其中一组带子的色标换成三个带子（宽、中、细），格纹立刻变得复杂，像真的花呢；两组带子不同是 tartan 的常规做法。
- 单层格里再套一层很淡的斜纹（`repeating-linear-gradient` 45°），能得到织物表面的斜纹感；那层用 `overlay` 而不是 `multiply` 会更自然。
