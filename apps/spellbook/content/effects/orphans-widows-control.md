## 描述

一段话跨到下一页时，上一页的末尾至少留两行，下一页的开头也至少有两行——不允许出现单独的一行撇在那里。

机制是 ==`orphans` 管段落**开头**被留下不够的行数，`widows` 管**末尾**被带走不够的行数==。两个属性只在**分片（fragmentation）**发生时才起作用——也就是内容要跨过一条分页边界或分栏边界的时候。它们不是「让段落更好看」的通用开关，而是「必须切断时，把断点挪到哪」的约束。

所以它们在屏幕上通常**看不出任何效果**。一整段话在一个不分栏的容器里根本不会分片，浏览器无事可做。这也解释了为什么很多人写了一次 `widows: 2` 之后觉得「没用」——不是属性无效，是当前没有断点可挪。

## 代码

```html
<div class="page">
  <p class="prose">段落要长到跨页才看得出效果。分页时，段落开头不允许只剩一行留在上一页，结尾也不允许只有一行被推到下一页——两个约束同时成立时，浏览器只能把整个句子挪到下一页，或者把上一页的行留得更多一些。这就是孤行与寡行的控制。</p>
</div>
```

```css
.prose {
  font: 400 15px/1.8 Georgia, "Songti SC", serif;
  /* @mechanism 段落开头至少留 2 行在本页 */
  orphans: 2;
  /* @mechanism 段落结尾至少带 2 行到下页 */
  widows: 2;
}

@media print {
  .page {
    /* @mechanism 造出分片边界，孤行控制才有机会生效 */
    columns: 1;
    /* @mechanism 整块不拆；与 orphans/widows 是粗细两档，通常只用一档 */
    break-inside: auto;
  }
}
```

## 边界

- 屏幕上**看不到效果**，因为没有分片边界。验证它只能靠打印预览或导出 PDF——放进 `<div style="columns: 2">` 里也能在屏幕上造出分栏边界来观察，但那是分栏而不是分页，浏览器的实现路径不完全一致。
- `orphans` / `widows` 与 `break-inside: avoid` 是两档：前者是「允许断，但断在合适的地方」，后者是「不许断」。两个一起写时，`avoid` 优先——整块不许拆了，孤行约束就没有用武之地。
- 值必须不小于 1，写 `0` 是无效值会被忽略。`widows: 1` 等于不管，且它与「不写」并不完全等价（部分实现里不写会用一个实现相关的默认值）。
- 约束太严时会互相打架：段落只有三行，又要求上下各留两行，数学上不可能。浏览器只能违反其中一个，各家的取舍不同，所以同一份文档在不同浏览器里分页结果可能不一样。
- 中文段落里这两个属性的收益比英文小：中文一行能容的字多、行与行之间的语义切分弱，孤行不显眼。真正需要它的是拉丁文排版的窄栏。
