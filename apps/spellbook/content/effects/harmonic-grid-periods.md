## 描述

细格上面压着粗格，粗线正好落在细线上，一根都没错位。

机制是 ==两层的周期取整数倍关系，粗线因此必然与某一根细线重合==。细格周期 w、粗格周期 4w 时，粗线的位置 0、4w、8w… 全部是细线位置 0、w、2w… 的子集，两层不会互相「打架」——粗线看起来只是那几根更亮的细线。这跟「两根线靠得近不近」无关，纯是周期整除的结果：只要不是整数倍，细线在每个大格里就会挪动一点相位，几格之后就贴到粗线旁边，整块看起来像被打乱了。

这条也在解释为什么版式网格里的模数（基线、栏宽、间距都取同一套倍数）能让页面看着整齐：不是因为它们数值好看，而是因为所有线都落在同一批位置上。反过来，想让两层故意错开、产生纹理感，就把周期取成非整数倍——那不是失误，是另一种意图。

## 代码

```html
<!-- @mechanism 细格与粗格共四条重复渐变，粗格周期是细格的 4 倍 -->
<div class="ruling"></div>
```

```css
.ruling {
  width: min(320px, 78vw);
  height: 168px;
  background-color: #0d0a14;
  /* @mechanism 细线每 --minor 一条，粗线每 4 倍一条：倍数关系让粗线正好压在细线上 */
  background-image:
    repeating-linear-gradient(
      90deg,
      rgb(217 164 65 / 0.3) 0 1px,
      rgb(13 10 20 / 0) 1px var(--minor, 14px)
    ),
    repeating-linear-gradient(
      0deg,
      rgb(217 164 65 / 0.3) 0 1px,
      rgb(13 10 20 / 0) 1px var(--minor, 14px)
    ),
    repeating-linear-gradient(
      90deg,
      rgb(217 164 65 / 0.85) 0 1px,
      rgb(13 10 20 / 0) 1px calc(var(--minor, 14px) * 4)
    ),
    repeating-linear-gradient(
      0deg,
      rgb(217 164 65 / 0.85) 0 1px,
      rgb(13 10 20 / 0) 1px calc(var(--minor, 14px) * 4)
    );
}
```

## 边界

- 1px 的线在 1× 屏幕上正好一个设备像素；在 2× 屏上是两个设备像素，看起来粗一倍。线越细越依赖设备像素对齐，换 DPR 或缩放页面，同一段 CSS 的粗细与浓淡都会变。
- 周期写 `px` 时横竖两个方向的周期是同一个数，格子是方的；改成百分比就糟了——百分比相对渐变轴长，而横向的轴长是元素宽、纵向是元素高，格子会被拉成长方形。
- 元素尺寸不是周期整数倍时，右侧与下侧会剩下半格被切开。每块元素是独立的相位起点，绝不会跟旁边的元素接上，所以并排的卡片之间格子永远对不齐。
- 想让格子随元素一起变大变小（自适应而不是固定密度），用百分比或 `cqmin` 定周期；想让格子密度恒定（无论元素多宽都保持 14px），用 `px`。这两种意图选错，小屏上格子会糊成一片。
- 两层都写 1px 的线时，粗线只是更亮、并不更粗。要把它加粗成 `0 3px`，粗线会从周期的起点向右长——细线占 0–1px（中心 0.5px），粗线占 0–3px（中心 1.5px），两者中心不再重合，主线看起来整体偏了一格。

## 备注

- 把粗格周期换成 5 倍、7 倍，就能做出「主格 + 副格 + 细格」的三级网格，只要全取同一个细格周期的整数倍，就永远对齐。
- 反过来把周期取成无理数比例（比如 √2 倍），细线会在每个大格里缓慢漂移，形成一种「不均匀但可预测」的纹理——那是设计选择，不是 bug。
